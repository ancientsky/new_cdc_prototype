# 原型功能與三階段路線圖對照

> 給誰看：要向主管或委員會說明「原型已經示範到哪裡、正式上線還缺什麼」的人。
> 依據：《疾管署官網 AI 應用與資料治理導入：盤點、規格與路線圖》（2026-09-22）。
> 說明：規劃文件把導入分三階段。第一階段「打底」（治理、資料與機讀基礎）、第二階段「重建」（新官網與 AI 問答上線）、第三階段為擴展與優化。**第三階段的細項以規劃文件原文為準**，本表只列原型中看得出方向的部分。
> 圖例：**已示範**＝原型可操作且邏輯完整；**部分**＝有骨架或僅示意；**未做**＝需正式環境才能做。

## 第一階段：打底

| 規劃項目 | 原型對應 | 狀態 | 還缺什麼 |
| --- | --- | --- | --- |
| 內容與資料盤點、統一識別碼 | `id` 規則、`content/` 結構、`legacyUrls`、`/v1/catalog.json` 五類資產總目錄 | 已示範 | 現行官網全量盤點與匯入（原型只有少量範例內容） |
| 治理欄位（權責、審閱日、週期、對象、敏感度、授權） | `schemas/_common.json`，缺欄位建置失敗 | 已示範 | 委員會確認欄位清單 |
| 審閱週期與到期管理 | 引擎計算 `nextReviewAt`／逾期；`/admin/due/` | 已示範 | 與機關公文／提醒系統串接 |
| 版本鏈與失效版本處理 | 獨立版本檔、`isCurrent`、noindex、301、異動對照 | 已示範 | 歷史版本回補（現行官網的舊 PDF） |
| 正本修訂連動衍生內容 | `basedOn`、橘色加註、7 日待辦、反向稽核（MMR 案例） | 已示範 | 更多反向稽核規則由各組提供 |
| 資料集授權與時效 | 授權許可清單、更新頻率逾期待辦、CKAN 快照 | 部分 | 與 data.cdc.gov.tw 正式同步 |
| 主檔：傳染病、疫苗、國家、單位 | `content/master/*` | 部分 | 99 種法定傳染病完整欄位、疫苗全品項 |
| 七語詞彙主檔 | `glossary.json`、`locked` 鎖詞 | 部分 | 詞彙擴充與各語言審核 |
| OpenAPI 與機讀出口 | `/v1/*`、`openapi.json`、`llms.txt`、`.md` 機讀版、JSON-LD | 已示範 | 正式網域、ETag 與限流 |
| AI 白名單政策 | `whitelist.json`＋引擎逐條算資格 | 已示範 | 委員會核准、擴大範圍的評估流程 |
| KPI | `/v1/governance/kpi.json`、`/admin/` | 已示範 | 目標值核定 |

## 第三階段方向（擴展與優化）

| 方向 | 原型的鋪墊 | 狀態 |
| --- | --- | --- |
| 更多內容型別與全站遷移 | 新增型別流程（見 [deploy.md](deploy.md)） | 部分 |
| Webhook 與 API 金鑰、限流 | [開發者入口](https://ancientsky.github.io/new_cdc_prototype/developers/)已描述格式 | 未做 |
| 個人化通知（訂閱） | 專區訂閱與 RSS/.ics | 部分 |
| 跨機關資料交換（如與衛福部、地方衛生局） | 統一 id、授權與正本欄位 | 部分 |
| 透明報告長期趨勢、外部稽核 | 季報 JSON 可歸檔 | 部分 |

## 原型到上線的最短路徑

1. **先做治理，再放 AI**：第一階段的欄位、版本鏈與白名單可以在不上 AI 的情況下獨立帶來價值（過期預警、舊版標示、API）。
2. **用一個完整案例驗證**：MMR 建議修訂這條線（正本、舊版、衍生新聞稿、反向稽核、版本題）已跑通，建議正式導入時先以麻疹／登革熱兩個主題為試點。
3. **評估集先於擴大範圍**：任何新增型別或語言，先有題目、再進白名單。
4. **把示意換成真實**：態勢數字、通函、核准紀錄與評估集題目是原型最需要替換的部分，詳見 [architecture-decisions.md](architecture-decisions.md) 的「示意資料」清單。

## 各階段怎麼驗收

| 階段 | 驗收看什麼 | 在原型哪裡看 |
| --- | --- | --- |
| 第一階段 | 對外內容 100% 有更新日與權責單位；資料集授權標示一致；現行文件都有機讀版；已修訂正本仍有未加註衍生內容為 0 件 | `/admin/` KPI 表、`/v1/governance/kpi.json` |
| 第二階段 | 版本題全對；六項評估指標達門檻；拒答精準度；暫停演練在 15 分鐘內完成；一級內容七語涵蓋 | `/transparency/`、`/admin/eval/`、`/admin/ai-status/` |
| 第三階段 | 季報連續發布；外部整合（API 使用者）可用；長期趨勢可追 | `/v1/governance/eval-report.json` 逐季歸檔 |

## 各單位在三階段的責任

| 單位 | 第一階段 | 第二階段 |
| --- | --- | --- |
| 各組 | 盤點名下內容、補齊欄位、指定 Steward | 正本審閱與修訂、處理待辦、提供評估題目 |
| 公關室 | 建立新聞稿與澄清的 `basedOn` 習慣 | 錯答回報分派、對外說明、Banner 管理 |
| 資訊室 | 建立 Git 與 CI、網域與資安 | 部署、排程、備援、紅隊技術支援 |
| OASIS | 欄位與詞彙標準、授權檢核、白名單政策 | 評估集、季報、委員會報告 |
| 疫情中心 | 態勢層欄位與門檻定義 | 每週態勢發布、nidss 資料集維護 |

原型把這些責任落實成欄位（`owner`、`steward`）與待辦分派，所以進入第二階段時，不需要另外再建一套責任表；單位名稱與對應關係以 `content/master/units.json` 為準。

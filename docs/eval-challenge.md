# 換句話說挑戰集（第四十九輪）

> 讀者：資訊室、OASIS（資料治理幕僚）、各組室內容承辦。同仁操作版見《同仁手冊》第 49 節。
> 檔案：`content/governance/eval-challenge.json`（題庫）、`eval/run-challenge.mjs`（執行器）、`tests/round49-challenge.test.mjs`（格式與「不擋建置」檢查）。
> 指令：`npm run eval:challenge`。

## 1. 為什麼要另外一份題庫

我們已經有評估集 `content/governance/eval-set.json`（327 題），每次建置都跑，版本題不全對就不能上線，目前全部通過。問題是：**這 327 題大多是官方題目的原文**，或是同仁照著 FAQ 標題寫的題目。答案引擎答得出「FAQ 標題原文」，不代表答得出民眾真正會打的字。

這是機器學習裡最老的一個道理——**拿考過的題目來打分數，分數一定好看**：

- 每次有人回報「這題答錯」，我們就修詞彙、調規則，再把那一題加進評估集。下次跑，那一題當然會過。
- 久了以後，評估集變成「我們已經修好的題目清單」。100% 通過只代表「修過的題都還是對的」，不代表「沒見過的問法也會對」。
- 就像學生只背考古題：考古題全對，換個問法就不會。老師要知道學生真的懂沒有，得出一份**學生沒看過的考卷**。

grokbot 最近兩輪測試正好是這個情形：評估集全過，但一般民眾的換句話說就出錯。例如第四十八輪 issue #102，「肺結核看病要錢嗎」「被流浪貓抓傷要打狂犬病疫苗嗎」引到的是正確的 FAQ，答案卻被標「與你的問題相關程度較低」；issue #94「打過什麼疫苗要去哪裡查」被當成「去哪裡打疫苗」，引到流感疫苗接種地點。這些題修好後都進了評估集，但下一批換句話又會出現新的。

這一輪的基準測量（第 5 節）把差距量了出來：**同一天、同一個引擎，評估集 326/326（100%），挑戰集 336/520（64.6%）。**

所以挑戰集的定位是：

| | 評估集 `eval-set.json` | 挑戰集 `eval-challenge.json` |
| --- | --- | --- |
| 內容 | 官方原文、已知問題的回歸題 | 民眾說法：口語、俗稱、錯字、簡寫、否定句、很短的句子、長輩與家長說法、跟情境綁在一起的問法；五種外語 |
| 用途 | 擋上線（版本題 100%；其他六指標有門檻） | 量「類化能力」：沒見過的說法答不答得對 |
| 建置 | `build.mjs` 每次都跑 | **不讀、不跑**；CI 也不跑 |
| 分數 | 必須高 | 是一個要追蹤的數字，不是門檻 |

## 2. 題目怎麼來、長什麼樣子

第一版（2026-10-14，520 題）由第四十九輪依下列來源各寫 3–5 種說法：

- 每則已發布的 FAQ（67 則）→ 220 題
- 每個已發布的申請服務（16 個）→ 52 題
- 每個疾病頁（16 個）的四個民眾主要問題：症狀、預防、疫苗、去哪裡看／怎麼治療 → 192 題
- 五大主題 × 五種外語（英、印尼、泰、他加祿、越）：登革熱、狂犬病（動物咬抓傷）、結核病、流感疫苗、移工健康檢查 → 56 題

題目格式與評估集相同（判分用同一份 `src/client/answer/judge.js`），多了幾個欄位：

```json
{
  "id": "CH-FAQ-rabies-bite-3",
  "category": "faq",
  "source": "faq.rabies-bite",
  "style": "長輩",
  "split": "dev",
  "q": "給狗仔咬到要打針嗎",
  "expect": { "refuse": false, "mustCiteAny": ["faq.rabies-bite", "disease.rabies"], "mustNotCite": ["faq.snakebite-first-aid", "faq.snakebite-dont", "topic.antivenom"], "lowRelevance": false }
}
```

- `category`：`faq`／`service`／`disease`／`multilingual`（報告依此分組）。
- `source`：這題是哪一則內容的換句話說；疾病頁加上面向（`disease.dengue#vaccine`）、外語題寫 `ml.<主題>@<語言>`。
- `style`：問法（口語、俗稱、錯字、簡寫、否定、短句、長輩、家長、情境）。
- `split`：`dev` 或 `holdout`，見第 3 節。
- `lang`：非中文才寫；`view`：專業模式題才寫 `pro`（目前只有醫療院所送驗的 3 題）。
- `expect` 優先用「**要引用哪些內容**」（`mustCiteAny`，任一命中即可）＋「**不能引用哪些**」（`mustNotCite`，例如狗咬不能引蛇咬）＋ `lowRelevance: false`（正確答案不能被標低相關）。**不用 `mustInclude` 比對字串**：換句話說的題目，答案措辭本來就會變，字串比對太脆。
- `mustCiteAny` 要把「同樣正確」的內容都列進去（例如問黃熱病證明，FAQ 與黃皮書服務頁都對）；只列一則，引擎引到另一則同樣正確的內容也會被判錯，分數就不誠實了。

## 3. dev 與 holdout：規則

每個來源題的 3–5 種說法，大約一半標 `dev`、一半標 `holdout`（依題目 id 的雜湊值決定，每個來源題兩邊都有）。

**dev（開發用）**

- 執行器會列出失敗明細（問句 → 實際引用了什麼）。
- 工程與內容同仁可以拿來找問題：缺同義詞、意圖判錯、拒答太早、低相關誤標。

**holdout（保留不看）**

- 執行器**只報分數**，預設不列題目明細（要看須加 `--show-holdout`，請只在稽核或寫報告時用）。
- **不得**看著 holdout 的失敗題去加同義詞、改規則。一旦這樣做，holdout 就變成另一份考古題，分數不再代表「沒見過的說法」。
- dev 與 holdout 分數應該差不多（基準：dev 64.1%、holdout 65.2%）。如果 dev 一直進步、holdout 不動，代表修的是「這幾題」而不是「這一類問題」——也就是過度擬合。這正是保留 holdout 要偵測的事。

**題目在兩份題庫之間怎麼移動**

1. **先修引擎，再升格**：dev 題目失敗 → 修引擎或補詞彙 → 確認那一題過了 → 才把它**複製**進 `eval-set.json`（給一個評估集的 category 與 id，例如 `R50-xx`），變成回歸題。不要把還沒修好的題放進評估集——評估集必須全過，放進去只會擋住建置。
2. **升格的題目一律從挑戰集移除，記在 `promoted`**：同一句話同時在兩份題庫，挑戰集的分數就會因為「評估集逼它一定要對」而虛高。所以升格時把題目從 `questions` 搬到檔案最上層的 `promoted` 清單（`id`、`source`、`q`、`split`、`promotedAt`、`to`），留下紀錄但不再計分。holdout 題原則上不升格（升格前一定有人看過它的失敗明細，它就不再是「沒見過」）；真的要升格，也一樣要移出。
3. **不要把 dev 改成 holdout、也不要反過來**。分錯了就刪掉重寫一題新的。
4. **定期換新 holdout**：每季從智慧問答查詢紀錄（`docs/ask-log.md`，`npm run ask-log:report`）挑 20–40 則**真實民眾問句**（已遮蔽個資、去掉可識別的情境細節），寫好 `expect` 後一律加成 `holdout`。真實問句比我們自己想的換句話說更準；用舊的 holdout 太久，大家遲早會「看過」。換下來的舊 holdout 可以改成 dev。

## 4. 怎麼跑、怎麼讀報告

```bash
npm run eval:challenge                       # 全部；今天日期取 BUILD_TODAY 或系統日期
node eval/run-challenge.mjs --today=2026-10-14
node eval/run-challenge.mjs --split=dev --verbose        # 只看 dev，附失敗原因
node eval/run-challenge.mjs --category=service --lang=vi  # 子集合
node eval/run-challenge.mjs --json=out/challenge.json    # 另存 JSON 報告（含各分組與失敗清單）
node eval/run-challenge.mjs --json                       # JSON 直接印到畫面
```

執行器永遠以結束碼 0 結束（題庫格式錯誤才回 2），不會讓任何流程失敗。

報告各段：

| 段落 | 看什麼 |
| --- | --- |
| 全部 | 通過率；「第一來源就對」＝第一個引用就是應引用的內容（比通過率嚴格，民眾通常只看第一張來源卡） |
| 不在答案索引 | 應引用的內容目前不在 AI 白名單（例如審閱逾期退出），這種題答不出來不是引擎的錯；另列「排除後通過率」 |
| 依切分 | dev 與 holdout 應接近；差太多見第 3 節 |
| 依內容類型 | FAQ、服務、疾病頁、外語 |
| 依語言、依問法 | 哪一種說法最弱（基準：長輩說法 45%、情境題 54%） |
| 失敗原因 | `refused`（不該拒答卻拒答，多半是 no-match）、`wrong-source`（引到別的內容）、`low-relevance`（引對了但被標低相關）、`forbidden-source`（引到明確不該引的內容）、`source-not-in-ai-index`（見上） |
| 失敗明細 | 只列 dev：`✗ id [切分·類型·語言·問法] 問句`，下一行 `→ 實際引用；應引用 …` |

JSON 報告（`--json=路徑`）欄位：`total／passed／pct／top1Pct／blocked／pctEligible`、`bySplit／byCategory／byLang／byStyle`（各有 total、passed、pct、top1Pct）、`byFailureKind`、`failures[]`（holdout 題預設只有 id、分組與 kind）。

**比較兩次結果**時看三件事：holdout 分數有沒有動（真進步）、dev 與 holdout 差距有沒有拉大（過度擬合警訊）、`source-not-in-ai-index` 有沒有增加（內容治理問題，不是引擎問題）。

## 6. 同仁怎麼加換句話說

1. 打開 `content/governance/eval-challenge.json`，在同一個 `source` 的題目後面加一題（id 接續編號，例如 `CH-FAQ-rabies-bite-5`）。
2. 寫民眾真的會打的字，不要修飾：錯字、簡寫、沒有標點、台語用字（「狗仔」）都可以。**不要**照抄 FAQ 標題或評估集已有的題目（測試會擋）。
3. `expect` 照同一來源的其他題抄：`refuse: false`、`mustCiteAny`（把所有同樣正確的內容都列進去）、必要時 `mustNotCite`、`lowRelevance: false`。真的應該拒答的（例如急症要撥 119），寫 `{ "refuse": true, "refusalKind": "emergency" }`。
4. `split`：自己想的說法，看同一來源 dev／holdout 哪邊少就放哪邊；**從查詢紀錄來的真實問句一律放 holdout**。
5. `node --test tests/round49-challenge.test.mjs` 確認格式（id 不重複、不與評估集重複、引用的 id 都存在、每個來源兩邊都有）。
6. 開 PR。挑戰集分數下降不會擋 PR；請在 PR 說明寫上新增幾題、dev／holdout 各幾題。

## 7. 不做的事

- 不讓挑戰集擋建置或 CI：它的價值在於「沒有人為了讓它通過而調整」。一旦變成門檻，就會被當成考古題修。
- 不在挑戰集用 LLM 改寫題目自動擴充：自動產生的換句話說有固定的模式，引擎很容易「學會那個模式」，量不出真實民眾的說法。
- 不把挑戰集放進後台 `/admin/eval/`：後台頁是給同仁看評估集現況的，混在一起容易讓人以為 64% 是上線門檻。

## 8. 第四十九輪結果（2026-10-14）

這一輪用 dev 失敗題修了引擎（見 `docs/ask-search-llm.md` §14），修好的 34 題 dev 升格進評估集（`R49-21`～`R49-52`、`R49-54`、`R49-56`），依第 3 節規則從挑戰集移到 `promoted`。題庫從 520 題變 486 題。

| | 基準（main 7ffb180） | 第四十九輪 |
| --- | --- | --- |
| holdout 264 題 | 172（65.2%） | 178（**67.4%**） |
| dev（同一批 256 題，含已升格的 34 題） | 164（64.1%） | 198（77.3%） |
| dev（升格後剩下的 222 題） | — | 164（73.9%） |
| 全部（現行 486 題） | — | 342（70.4%；排除不在答案索引的 21 題後 73.5%） |

怎麼讀這張表：

- **能直接比較的只有 holdout**：題目沒變、沒人看過明細。65.2% → 67.4%，進步 2.2 個百分點（6 題）。
- **dev 進步 13 個百分點、holdout 只進步 2 個**。這個差距就是第 3 節說的過度擬合訊號：這一輪修的規則（動物咬傷排除、服務頁的主題比對、FAQ 優先於安全拒答）有一部分只對 dev 裡那幾種說法有效。這是預期中的現象，不是失敗，但它告訴我們：**下一輪不能只看 dev 分數宣稱進步**，要看 holdout。
- 「升格後剩下的 dev」比較低（73.9%），是因為修好的題目被搬走了，剩下的本來就是比較難的；這個數字只拿來跟下一輪的同一批題比。
- 失敗 144 題：引到別的內容 47、不該拒答卻拒答 42、引對但被標低相關 34、應引用的內容不在答案索引 21（屈公病、日本腦炎疾病頁審閱逾期，自動退出 AI 白名單；請權責組室重新審閱）。
- 最弱的說法仍是長輩說法（56.3%）、情境題（60.7%）、服務頁換句話說（58.7%）、印尼文（45.5%）與泰文（50%）。

完整報告存於共用資料夾 `eval-challenge/round49-2026-10-14.json`。

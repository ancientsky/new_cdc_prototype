# 《疫情報導》重新設計：像 MMWR 一樣直接讀全文，也能下載 PDF（第二十九輪）

> 給出版單位（疫情中心）、資訊室與 OASIS。這份文件說明新站把《疫情報導》改成什麼樣、為什麼這樣改、上架流程怎麼變簡單、哪些是示範內容、正式上線前要補什麼。同事操作步驟在 [guide-staff.md §32](guide-staff.md#32-疫情報導文章怎麼上架第二十九輪)；程式契約在 ARCHITECTURE §34；決策理由在 architecture-decisions §21。

## 1. 現況與同事提出的問題

舊站的「疫情報導」頁（`/EpidemicTheme/Index/…`）是一個卷期清單：點進某一期看到篇名與摘要，全文要開整本 PDF。原型前幾輪照這個模型做了 `publication`（卷期＝一筆出版品，`articles[]` 是篇目清單），所以也只有「書目＋整本 PDF」。

同事反映兩件事：
1. **讀**：想像美國 CDC 的 MMWR（Morbidity and Mortality Weekly Report）一樣，點一篇就直接看全文 HTML，要 PDF 再下載。
2. **上架**：目前上架很麻煩。以舊模型來說，每加一篇要回頭改卷期 JSON 的 `articles[]`、對頁碼、調順序、再上傳整本 PDF；一期四篇就改同一個檔四次，最容易出錯的是頁碼與順序。

## 2. 我們向 MMWR 借了什麼、沒借什麼

MMWR 文章頁的幾個特徵（依公開的 MMWR 作者指引與網站版面整理；開發環境連不到 cdc.gov，未逐頁核對）：文章是閱讀單位；頁首是卷期、日期、作者與單位；正文前有 **summary box**（What is already known / What is added by this report / What are the implications for public health practice）；正文直接攤開，圖表就地編號；側欄有 PDF、引用格式、相關文章；每篇都有穩定網址與建議引用寫法。

| MMWR 的做法 | 新站怎麼做 | 為什麼 |
| --- | --- | --- |
| 一篇文章一個網址、全文 HTML | 新型別 `article`，網址 `/publications/{卷期}/{篇次}/`，`sections[]` 渲染成 HTML | 讀者、搜尋引擎、智慧查詢都能直接到「某篇的某一段」；PDF 變成另存，不是唯一入口 |
| summary box 三句話 | `highlights.known / added / implications`，文章頁「重點」框 | 讀者 30 秒內決定要不要往下讀；也是智慧查詢最好引用的一塊 |
| 摘要在正文之前 | `abstractMarkdown` → 頁首摘要框 | 同上 |
| 圖表編號、就地插入 | `figures[]`（圖或表、編號、說明、Markdown 表格或圖檔＋替代文字），放在正文第一次提到它的那段之後 | 表格直接是 HTML 表格：可搜尋、可朗讀、可複製；圖一定有文字版 |
| 建議引用格式 | 中、英兩種格式各一個複製鈕；`/v1/articles.json` 也帶 | 研究者與媒體引用時不必自己拼 |
| 整期目錄 | 卷期頁改成「本期目錄」：篇次、類型、頁碼、篇名、作者、摘要一句、全文與 PDF 鈕 | 一期的全貌一眼看完；舊式只有書目的篇目照舊列出並標「僅書目」 |
| 單篇 PDF | `pdfUrl`（單篇）→ 沒有時退回本期 PDF → 再沒有就提供「列印／另存 PDF」 | 不要求出版單位一定要拆 PDF；列印樣式是乾淨的文章版面，瀏覽器另存即可 |

**沒借的**：MMWR 的英文排版字型與欄寬（新站沿用自己的設計系統）；MMWR 的 Altmetric、社群分享（原型不接第三方）；MMWR 把每篇再轉成多種格式（RIS、BibTeX）——先給中英文引用字串，格式匯出可以之後加。

**為什麼不用第二十一輪的長文件收合版面**：那個版面是給上百頁的指引用的（章節卡＋每節收合）；期刊文章只有 4～6 段、一次讀完，收合反而多一次點擊。文章頁改用「正文攤開＋右側黏住的目錄」。

## 3. 資料模型：文章是一筆內容，卷期由文章組成

```
content/publications/bulletin-42-13.json   卷期（既有的 publication，pubType bulletin）
content/articles/teb-42-13-1.json          文章 1（type article，issueId 指向卷期，articleNo 1）
content/articles/teb-42-13-2.json          文章 2
content/assets/article.teb-42-13-1/x.pdf   單篇 PDF（選填）
```

- `article` 有完整的治理欄位（權責單位、審閱、AI 白名單、verification），所以每篇都能獨立複核、獨立標「待確認」、獨立進白名單。
- 卷期頁的目錄**在建置時**由 `issueId` 相同的文章算出來（`src/client/bulletin-rules.js` 的 `issueToc`）；卷期 JSON 裡舊的 `articles[]` 仍可用，沒被同篇次全文取代的篇目照舊列出。兩種模型並存，舊資料不必一次搬完。
- 建置閘門（`scripts/lib/validate.mjs`）擋：卷期不存在或不是 bulletin、同期篇次重複、頁碼與同期其他篇重疊、沒有正文、沒有作者。這些規則與後台共用同一份程式，所以後台說「通過」，CI 就一定通過。
- 文章同時進：智慧查詢索引（摘要、重點、每一段、每個圖表各一塊，引用連到 `#s-{key}`、`#table-1`）、Pagefind 全文搜尋、`/v1/articles.json`、出版品 RSS、sitemap、JSON-LD（`ScholarlyArticle` → `isPartOf` `PublicationIssue`）。

## 4. 上架流程怎麼變簡單

舊：承辦人要同時維護卷期 JSON 的篇目清單、頁碼、順序與整本 PDF。

新：`/admin/bulletin/edit/`，一篇一次。
1. 選卷期（或填卷、期、出刊日建新的一期；系統建議下一期號）。篇次自動帶「本期最大篇次＋1」。
2. 把整份稿件從 Word 貼進來，按「自動切段」。系統認得「摘要／前言／方法／結果／討論／結論／誌謝／參考文獻」（含「一、」「1.」「【】」等寫法），把「圖 1 …」「表 1 …」抽成圖表說明，參考文獻逐行去編號。切不出來的文字列在「放不進任何章節」讓人處理，**不猜**。
3. 核對作者（每行「姓名 | 單位 | *」）、頁碼、重點三句話、圖表內容；右側即時長出文章頁與本期目錄，點預覽區塊跳欄位（沿用第二十二輪的做法）。
4. 「檢核」頁籤全綠才能「產生上架包」：文章 JSON、（新卷期時）卷期 JSON、單篇 PDF。解壓到 repo 開 PR，走一般車道。
5. 前台文章頁頁尾「同事修改這頁」直接開回這個表單（`?edit=文章 id`），修改既有文章時表單沒有的欄位（languages、i18n…）原樣保留，PR 只多出真正改動的部分。

草稿自動存在這台電腦的瀏覽器（`cdc.admin.bulletin-edit`），Ctrl+S 立即存。

## 6. 正式上線前要補的事（給疫情中心／資訊室）

1. **以真實文章取代示範**：每篇文章從後台重新上架（或請 OASIS 用 `scripts/pdf-to-md.mjs` 從單篇 PDF 轉出 `sections`），`verification` 改 `confirmed`。
2. **單篇 PDF**：出版單位若能提供單篇 PDF，放 `content/assets/article.{id}/`，文章頁的「下載 PDF」就變成單篇；提供不了也沒關係，退回本期 PDF 與列印版。
3. **歷年卷期**：舊站歷年各期可用舊站匯入批次（[legacy-import.md](legacy-import.md)）先建卷期與書目篇目，再逐篇補全文；不必一次補完。
4. **作者姓名**：示範用單位代稱；正式內容依刊載格式填真名與單位（出版品署名是公開資訊，不受個資遮罩規則限制）。
5. **引用格式**：目前中文格式是「作者。篇名。疫情報導 2026；42（13）：1-8。」，請出版單位確認期刊自己的規範，改 `src/client/bulletin-rules.js` 的 `citationOf` 一處即可。
6. **DOI**：每篇都有 DOI（第三十五輪起必填級的提醒；格式與移轉做法見 §9）。

## 8. 作者的服務單位上標與通訊作者星號

**問題：** 多位作者、多個服務單位時，刊載格式是「李泱 ^1*^、戴詩縈 ^1^、…、林稜 ^2^」，下面列「1 北區管制中心」「2 急性組」，通訊作者加星號並印 E-mail。在 Markdown 編輯要怎麼做到？

**答：不用在 Markdown 裡打上標。** 作者與單位是**結構化欄位**，不是正文；上標、星號、單位清單、通訊作者 E-mail 都由模板依資料自動排出來，三個地方（文章頁、引用格式、JSON-LD）才會一致，也不會有人把 `^1^` 打成 `^1` 排版壞掉。

- 文章 JSON：`affiliations[]`（`no`、`name`、`nameEn`）＋每位作者的 `affiliations: [1, 2]`、`corresponding: true`、`email`、`nameEn`。
- 後台作者欄一行一位：「`姓名 | 單位編號 | * | E-mail | 英文姓名`」；服務單位欄一行一個：「`編號 | 中文名稱 | 英文名稱`」。只有一個單位時編號可省略，前台也不會印上標（跟刊物一樣）。
- **從 PDF 貼進來會自動抓**：作者列「王大明 1*、李小華 1、陳美玲 2」、腳註式的「1 單位名稱」「通訊作者：」「E-mail：」都認得（第 8.2 節）。
- 正文若真的需要上下標（化學式、10^6^ CFU），Markdown 用 pandoc 慣例 `^上標^`、`~下標~`，建置與後台預覽同一條規則（`scripts/lib/markdown.mjs` 與 `src/client/admin/md-convert.js` 的 `supSub`）。

為什麼不用 HTML 或 Markdown 上標寫作者列：作者列要被三種輸出重用（HTML、引用格式、JSON-LD `author` 的 `affiliation`），寫成文字就得三處各自解析；而且無障礙讀者聽到的會是「1 星」而不是「服務單位 1，通訊作者」。模板現在替上標加了 `sr-only` 說明，螢幕報讀器唸得出意思。

### 8.1 檢核

後台與 CI 同一套規則（`articleProblems`）：作者引用不存在的單位編號 → 擋建置；有單位沒人引用、沒標通訊作者、通訊作者沒 E-mail → 提醒。

### 8.2 稿件切段對 PDF 文字的支援

同事最省事的做法是「把 PDF 全選複製、貼進後台稿件框、按自動切段」。`splitManuscript` 這一輪學會了刊物 PDF 的版面：

| PDF 裡的東西 | 處理 |
| --- | --- |
| 頁首「2026 年 10 月 6 日 第 42 卷 第 19 期」、頁尾「疫情報導 186」、分類標頭「│疫情調查│」、「衛生福利部疾病管制署」 | 當頁面裝飾去掉；卷期與出刊日拿來**自動選卷期**（沒有就幫你新建），頁碼範圍從頁尾算出 |
| 作者列（含上標數字與 `*`）、腳註「1 單位」「2 單位」、「通訊作者：」「E-mail：」「投稿日期」「接受日期」「DOI：」「關鍵字：」 | 填進對應欄位；關鍵字折成兩行也接得起來 |
| 折行（PDF 每行約 35 字）、「一、小標」 | 同段接回一行；「一、」「二、」小標變 `###` |
| 「圖一、說明」 | 圖表列；正文「如圖一」「圖 1」「Fig. 1」都算有提到 |
| 參考文獻編號單獨一行、英文文獻折行 | 接成一筆一筆 |
| 英文摘要頁（Abstract、Keywords、英文作者列、英文篇名） | `abstractEn`、`keywordsEn`、`nameEn`、`titleEn` |
| 「摘要」之前的篇名 | 篇名（括號收尾如「（上）」也認得） |
| 英文頁 DOI 與中文頁不同 | 標成 `doiConflicts` 提醒（這篇真的有：英文頁印 `2026010`，少一個數字） |

沒認出的行進「未歸類」框，不會丟。切段報告會列出抓到哪些欄位；**抓到的只是起點，同事仍要逐段核對**（這一條在後台文字裡反覆提醒）。

## 9. DOI：補欄位、怎麼轉址、舊文章怎麼對應

**問題：** 每篇都有 DOI，目前 DOI 指到現行網站文章頁；改版後舊文章怎麼對應和轉址？原型沒有 DOI，請補上。

**先講原則：DOI 永遠不變，變的是 DOI 登記的「落地網址」。** `https://doi.org/10.6524/EB.202610_42(19).0001` 這個識別碼會一直印在 PDF 與別人的引用裡；doi.org 只是查一張「DOI → 網址」的表，把人轉到登錄機構（這個前綴 `10.6524` 是華藝 Airiti）登記的網址。所以移轉要做兩件事，不是改 DOI：

1. **請登錄機構批次更新落地網址**：新站建置時輸出 `v1/doi.json`（每篇 `doi`、新網址 `url`、目前登記的舊網址 `legacyDoiUrl`），直接給出版單位交登錄機構做批次更新（CrossRef／Airiti 都有批次更新 URL 的機制，不用一筆一筆改）。
2. **舊網址 301 到新文章頁**：登錄機構更新之前（以及搜尋引擎、別人的書籤），舊站文章頁網址（`https://www.cdc.gov.tw/EpidemicTheme/Index/…`）填在文章的 `legacyDoiUrl`，建置就把它放進既有的 301 對照（nginx／IIS／`_redirects` 三種格式都有，見 [deploy.md](deploy.md)）。兩邊都做，哪一邊先生效都對。

另外提供**站內解析路徑** `/doi/10.6524/EB.202610_42(19).0001` → 301 到文章頁。好處是出版單位可以把 DOI 落地網址登記成「`https://新站/doi/{DOI}`」這種**穩定的形式**，以後文章網址再怎麼改（例如又改版一次），只改站內對照、不必再找登錄機構。

### 9.1 欄位與檢核

- `doi`（字串，只填 `10.6524/…`，不含 `https://doi.org/`）、`legacyDoiUrl`（舊落地網址）。
- 後台「建議 DOI」依刊物慣例 `10.6524/EB.{出刊年月}_{卷}({期}).{篇次四位}` 產生（從真實 DOI 歸納）；**出版單位有給正式 DOI 以它為準**，建議只是省打字。
- 檢核：格式不對、與其他文章重複 → 擋建置；卷期或篇次與所屬卷期不符、不符慣例 → 提醒；沒填 → 提醒。
- 前台：頁首「DOI 連結＋複製」、引用格式尾端 `doi:…`、JSON-LD `identifier`（PropertyValue DOI）、機讀版 `.md`、`v1/articles.json` 的 `doiUrl`。
- 轉址：`v1/redirects.json` 多一種 `kind: doi`；`/doi/{DOI}` 與 `legacyDoiUrl` 都進伺服器對照檔。

### 9.2 舊文章（歷年）怎麼辦

歷年文章先用舊站匯入批次建卷期與書目篇目（第二十九輪的 legacy 篇目），每筆帶 `doi` 與 `legacyDoiUrl` 就夠讓 301 與 `v1/doi.json` 成立——**不必等全文補完才能轉址**。全文之後逐篇補。

## 10. 文章分類：做在主檔，後台可以加

**問題：** 官網左側有「原著文章、疫情調查、焦點特寫、國內外疫情焦點、疫調快報、生安專欄、疫苗專欄、重要疫訊」；原型能不能做？要加新類別後台怎麼做？

**答：分類是一個主檔**（`content/master/bulletin-categories.json`，八筆，照官網順序），不是寫死在程式裡：

- 文章的 `articleType` 必須是主檔裡的代號（建置會擋；第二十九輪的舊代號 `outbreak-report`、`surveillance`… 自動對到新分類，舊 JSON 不用改）。
- 前台多了 **《疫情報導》總覽頁** `/publications/bulletin/`（簡介、分類導覽、最新文章、最新卷期）與**每個分類一頁** `/publications/bulletin/{代號}/`（依年份分組，七語都有）；文章頁與卷期目錄的分類徽章連到分類頁。這就是官網左側那欄。
- API：`v1/bulletin-categories.json`（含每類篇數）；`v1/articles.json` 的 `category {key,label,labelEn}`。
- **後台加分類**：文章後台 H 區「文章分類管理」填中文名、英文名，按「新增」；代號由英文名自動產生（`case-report`），立刻出現在分類下拉。產生上架包時若分類主檔有改動，包裡多一個 `content/master/bulletin-categories.json`，資訊室合併後前台就有這個分類的列表頁。不想再用的分類勾「停用」（`retiredAt`）：舊文章保留，下拉不再出現，沒文章的停用分類不產生頁面。

為什麼不做成「後台打一個新字串就算新分類」：分類要產生列表頁、要有英文名、要進 API，必須是有代號與順序的主檔；而主檔改動與文章一起進同一個上架包，才不會出現「文章用了新分類、主檔還沒改、建置被擋」的時間差。

## 11. 圖片：最省功的放法

**問題：** 這篇文章有兩張圖，上架時怎麼最省功放進 HTML 全文？

**答：把圖檔拖進後台，其餘自動。** 流程（實測見 §12）：

1. 從 Word 或 PDF 把圖另存成 PNG（或截圖），檔名取「圖1.png」「圖2.png」（「fig-1.png」「表1.png」「Figure 2.jpg」都認得）。
2. 拖到後台 F 區「圖與表」（或用選檔按鈕，可多選）。系統依檔名配到對應的圖表列（沒有那一列就新增），改成標準檔名 `fig-1.png`、算 sha256、讀寬高、宣告進 `assets[]`（`kind: image`、授權 OGDL-1.0），預覽立刻看得到圖。
3. 補一句**替代文字**（無障礙必填，沒填會擋建置）。
4. 產生上架包：圖檔自動放進 `content/assets/article.{id}/`。

文章頁把圖放在**正文第一次提到它的段落後面**（「圖一」「圖 1」都認得），不用在 Markdown 裡手打 `![]()`；想改位置才用 Markdown。圖檔大小上限 2 MB（`imageMaxBytes`，超過會提示先壓）。

給資訊室的批次做法：`pdfimages -png 文章.pdf 圖` 可把 PDF 內嵌圖直接抽出（這篇實測抽到 4 張：1 張是圖一、2 張是刊頭小圖、1 張是流程圖的重複版本），挑對的改名即可；頁面截圖請用 `pdftoppm -r 150`。

## 14. 上傳 PDF 自動帶入、審批後直接上架（第四十五輪，2026-10-13）

同事問：**能不能上傳疫情報導的 PDF 後，後台自動 parsing 成需要的欄位與全文，審批後上架，不要再人工逐一欄位填寫？** 答案是可以，而且原型已經做出來：上傳一份排版好的 PDF，欄位、全文、圖片全部自動帶入；同事核對後按「送審」，科長在審核頁按「核准上線」，文章、卷期、PDF 與圖就進正式庫，整個過程不碰 Git、不打包 ZIP。

### 14.2 自動帶入哪些東西、怎麼帶

- **文字**：pdf.js 的 `getTextContent()` 回的是一塊一塊的字與座標，沒有「行」。`src/client/admin/pdf-manuscript.js` 依座標把字塊排回行（同一基線＝y 差不到半個字高；同行依 x 排序；字塊間距超過 0.25 em 補一個空白，超過 1 em 依距離補多個），頁與頁之間空一行，產出的文字就跟 `pdftotext -layout` 幾乎一樣。所以**切段規則不用再寫一套**：第三十五輪為「貼 PDF 文字」寫的 `splitManuscript` 原封不動，用真實文章 42(19) 驗過：篇名、7 位作者（含上標與通訊作者）、2 個服務單位、DOI、投稿／接受日期、關鍵字、分類、摘要、7 段正文、圖說、11 筆參考文獻、英文摘要全部抓到。
- **圖片**：讀每頁的繪圖指令，把 `paintImageXObject`／`paintInlineImageXObject` 畫到 canvas 轉成 PNG。規則：寬小於 150 或高小於 80 的略過（刊頭小圖、符號）；同尺寸同指紋在兩頁以上出現的略過（頁首頁尾裝飾）；其餘依「圖 N」圖說所在頁（同頁、前一頁、下一頁）配對；配不到的列成縮圖讓同事指定。42(19) 的結果：圖 1 配到、刊頭大圖列為未配對、刊頭小圖略過。
- **PDF 本身**：同一份檔案直接成為「單篇 PDF」附件，不用再上傳第二次。

### 14.3 送審與上線怎麼接

寫入閘道（第三十輪）原本只收一個 JSON；本輪讓 `/drafts` 與 `/submit` 多收兩樣東西：

- `files[]`：附件（base64），存進分支的 `content/assets/{文章 id}/`，之後每一版沿用，不必重傳；
- `companions[]`：配套內容，例如新的一期 `publication`，因為文章的檢查會查「所屬卷期存在」，新一期的第一篇若沒有把卷期一起送就過不了檢查。配套內容與文章同一個分支、同一次核准、一起上線。

閘道的檢查**仍然是建置那一套**：附件放進暫存目錄，用 `validateAssets` 查 bytes、sha256、副檔名與內容是否相符，查完即刪。所以「後台通過＝CI 通過」在有附件之後仍然成立；實測故意改一個位元的圖檔，閘道回「sha256 不符」擋下。

上限：單次整包 24 MB、附件合計 16 MB、最多 20 個檔、檔名只許英數與 `._-`；內容本身仍限 512 KB（附件不算在內）。

### 14.4 限制（請同事知道）

1. **掃描的 PDF 沒有文字層**，讀不到字（會告訴同事「請把文字貼進稿件欄」）；圖還是抽得到。
2. **向量圖**（用排版軟體畫的流程圖、折線圖）不是內嵌圖片，抽不出來；同事仍要自己存成 PNG 拖進來（第三十五輪的做法）。表格通常是文字，不當圖處理。
3. **最多讀 60 頁**；疫情報導單篇通常 5–10 頁。另外每頁最多取 15,000 個字塊、字塊與每行裡的連續空白收斂到 40 個（2026-10-21 資安檢查補的：特製文字層塞同列幾萬個字塊或幾萬個空白會讓後台頁面卡住好幾秒；真實稿件一頁只有幾百到兩三千個字塊，碰不到上限）。
4. 刊頭的分類名是加寬字距的「疫 情 調 查」，文字層會變成字與字之間有空白，切段規則比對分類時先把空白拿掉（本輪補的）。
5. 帶入的是「稿件文字」，不是排版：圖說與圖的對應、上下標（`^x^`）、表格，核對時請看預覽。

正式環境若有後端，可以改在伺服器用 `pdftotext -layout` 產文字再丟給同一套 `splitManuscript`（`scripts/lib/pdf-text.mjs` 第十九輪已有包裝），瀏覽器端就不必載 pdf.js；兩條路的切段規則相同。

### 14.6 這一輪學到的事

- **pdf.js 會把 ArrayBuffer「轉移」給 worker**：交給 `getDocument` 的 bytes 讀完後長度變 0，第一次實測送審的 PDF 附件是空的（sha256 等於空檔案的雜湊）。交出去前先複製一份。
- **要用 pdf.js 的 legacy 版**：一般版用了 `Map.prototype.getOrInsertComputed` 這類 2025 年才進瀏覽器的語法，Playwright 附的 Chromium 載入就壞；legacy 版自帶 polyfill。機關電腦的瀏覽器版本不一定新，vendor 一律放 legacy 版。
- **vendor 檔名用 `.js` 不用 `.mjs`**：IIS 這類伺服器預設不認 `.mjs`（回 404 或 `application/octet-stream`），瀏覽器會拒絕當模組載入；`.js` 走哪裡都通。本機預覽伺服器也補了 `.mjs` 的 MIME。
- **圖物件要用回呼版拿**：`page.objs.get(name)` 在圖還沒解碼完時會丟錯（`has()` 回 false）；用 `objs.get(name, callback)` 等它解完（最多 8 秒）才拿得到第 2 頁那張圖。
- **讀 Git 裡的二進位檔不能經過字串**：本機 Git 供應者原本把 `cat-file` 的輸出一律 `String()`，圖檔讀回來多了 80%（UTF-8 把非法位元組換成替代字元）；第二次「不重傳附件再存一版」因此被自己的 sha256 檢查擋下。`binary` 模式要原樣回 Buffer，GitLab 供應者則走 `arrayBuffer()`。
- **暫存目錄不要出現在同事看到的訊息裡**：附件檢查在暫存目錄做，錯誤訊息原本印 `../../../tmp/gw-assets-xxxx/…`；閘道回傳前把它換回 `content/assets/…`。

#### (c) 表格還原規則（用白話說）

pdf.js 給的只是一塊塊的字與座標。要排成表格，`tableToMarkdown` 照下面做：

1. **先分儲存格**：同一行裡字塊間距超過 0.6 個字高就切成不同儲存格。**為什麼先做這步：** pdf.js 會把一個儲存格拆成很多字塊（「案 1」可能是「案」與「1」兩塊），直接用字塊當欄會把它切碎。
2. **再找欄的起點**：把儲存格左緣聚類（至少 2 行對得上）；數字緊密相連的欄（例如「33 (45.2) 24 (32.9)」，四個數字在同一個儲存格裡）改看儲存格**內部**字塊的起點（至少 40% 的行、且至少 3 行）。**為什麼是兩層：** 純看欄起點會切碎「案 1」；純看間距又分不開「33 (45.2) 24 (32.9)」。見 ARCHITECTURE §49.4。
3. **字塊歸欄**：左緣對得上欄起點就歸該欄，否則看中心點落在哪一欄的範圍。
4. **合併不會同時有字的欄**：相鄰兩欄若沒有任何一行同時都有字，視為同一欄。**為什麼：** 表頭置中、數字靠右的欄會被誤判成兩個起點。
5. **表頭列**：第一個「資料列」（第一欄有字、且有以數字開頭的格）之前，全部都是表頭，逐欄合併。**為什麼逐欄：** 直排單字的表頭（一字一行）才接得回來。
6. **列名依 y 距離歸屬**：列名垂直置中、或列名折成兩行時，「只有列名」的行歸給 y 距離最近的「只有數值」的行；「只有數值」的行接在上一列後面（`<br>` 續行）。
7. **跨頁**：「(續上頁) 表 N」接回同一個表；「(接下頁)」丟掉；只剩表頭的跨頁殘段（沒有資料列、多半是單字格）不輸出 Markdown。
8. **表頭上層**：蓋住兩欄以上的文字表頭（例如「船種檢查艘次(n=836)」）不放進表格，另記成一行 `（表頭上層：…）` 掛在表下。**為什麼：** Markdown 表格沒有合併儲存格，硬塞進某一欄會誤導。
9. **表下註解**：`a.`、`註`、`*` 開頭的行掛在該表之後。

稿件文字裡，表的樣子是：`表一、…` 圖說行 → `|` 開頭的 Markdown 列 → 註解行。`splitManuscript` 把這些行掛到剛剛那個「表 N」的內容，E 區因此直接有表格內容（`bulletin-edit` 顯示「N 個表格已還原成表格內容」）。例（b 表二，緊密欄）：

```
| 船種/區域 | 廚房 | 倉庫 | 配膳室 | …
| 油輪 | 33 (45.2) | 24 (32.9) | 19 (26.0) | …
```

b 的四個表都還原：表一 49 行（跨 p3–p4 接回同一個表，重複的表頭與註解只留一份）、表二 18 行、表三 11 行、表四 16 行；c 的鍵值式表格 16 行；d 的兩個表 19 行與 4 行；e 的三個表 13、11、10 行。

#### (d) 圖內文字略過

向量圖（g 的折線圖）的座標軸刻度、圖例、資料標籤在文字層裡是一堆零碎數字，若進正文會污染段落。`chartTextLines`：在「圖 N」圖說往上，連續的 ≤30 字短行中，只要有 **≥3 行是純數字**，就判定是圖內文字，略過並留一行標記「〔圖內文字 N 行已略過〕」；`splitManuscript` 把標記合併成一則 report「圖內的文字已略過，請確認圖檔有一併上傳」，標記行本身丟掉。**為什麼用「純數字行」判斷：** 正文的短行（小標題、單位）很少連續三行都是純數字，誤殺機率低；而且只看圖說上方，不會碰到正文。

#### 其他新的切段規則（`splitManuscript`）

- **篇名**：從作者列往上找最多 3 行短行合併（可隔一個空行；分類名、刊頭日期行不算）。
- **作者列**：結尾是「、,，」時與下一行合併；舊版的上標數字另成一行放在作者列上方（「1 1 2 3」）時，依序配給作者。
- **單位**：「1 單位」「1.單位」「1單位」同行，或「1」「2」接著兩行都認。全部作者同一單位且沒有編號時，取投稿日期／通訊作者附近**唯一一行**機構名當單位 1 配給所有作者（`AFF_NAME_OK`：含機構詞、無標點、長度有上限）。
- **整期合刊**：第二個「摘要」之後切掉放「未歸類」，report 提醒請改單篇 PDF。
- **沒有章節標題**（焦點特寫）：全文當一段「正文」（key `body`），report 提醒摘要自填。
- **沒有篇名也沒有作者列**（國內外疫情焦點）：以分類名代入，report 提醒改正式篇名。
- **`FIG_RE`**：中文數字後必須接「、」或空白才算圖說。**為什麼：** 「圖二為…」是句子不是圖說，之前被誤認而把正文切斷。
- **DOI**：只認行首、兩個空白後、全形空白後的 `DOI:`（參考文獻裡的 DOI 不算）；出現兩個不同 DOI 時採第一個並 report。

#### (e) 已知限制

1. **舊版（2013 以前）PDF 的文字層逐字有空白**（「8 ,2 4 5」）：欄位與表格結構抓得到，但**數字裡會有空白，需人工清**。
2. **列名垂直置中、且上下兩列都是完整的列**時，折行的值可能掛到相鄰那一列（c 表中「一般區第 17 床」是已知例子）。
3. **表格第一個資料列自己有折行**時，折行的上半會併進表頭（b 表三「生熟食交叉／污染」）。
4. **掃描 PDF**（無文字層）、**向量圖**（只能略過文字，沒有圖檔可抽）仍不支援；**整期合刊只帶第一篇**。
5. **無編號的「表、」**（f）只在稿件欄留下 Markdown 表格文字，不會成為 E 區表格項目；要的話請同事手動新增。
6. 「依版面推測的標題」（c、d、e、g、h 的 report）是依版面推測的（確切依據請看 `bulletin-rules.js`），**可能猜錯**，所以一律要同事核對。

#### (f) 怎麼驗

用拋棄式的小腳本（不進 repo）在 Node 裡用 pdf.js legacy 版讀 PDF，字塊交給 `manuscriptText`，再交給 `splitManuscript`，印出欄位、段落、report 與表格 Markdown。**走的程式碼和瀏覽器完全相同**——`pdf-manuscript.js` 與 `bulletin-rules.js` 是純函式，不依賴 DOM，所以 Node 的結果就是同事在瀏覽器看到的結果；只有 `pdf-read.js`（跟 pdf.js 講話、抽圖）是瀏覽器專屬。九份樣本的輸出就是 (a) 表的來源。

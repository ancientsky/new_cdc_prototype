# 無障礙基準與自我評量

> 第二十四輪新增。給資訊室、前台維護同事與稽核人員：本站以什麼標準為目標、WCAG 2.2 比 2.1 多了什麼、現在做到哪、CI 怎麼把關。
> 原則：**機器能判定的由 CI 擋，機器判不了的明說「待人工稽核」**，不假裝全部合格。

## 1. 目標標準

- 數位發展部「網站無障礙規範」2026-05-29 修正、**2026-11-30 施行**，新增 WCAG 2.2 的成功準則。本站目標：**新版網站無障礙規範 AA 等級（對應 WCAG 2.2 AA）**。
- 依據：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)；規範法源：[全國法規資料庫（K0060095）](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=K0060095)。
- 為什麼不停在 2.1：2.2 的新增項目多半是行動裝置與認知、動作障礙者的實際痛點（點不到、被遮住、重複輸入），而且 2026-11-30 後是法定基準；現在補的成本最低。決策記錄見 [architecture-decisions.md](architecture-decisions.md) 第 16 節。

## 3. 自我評量（第二十四輪時點）

「符合」＝已由自動檢測或程式碼結構確認；「待人工稽核」＝需要人用鍵盤、螢幕閱讀器或真機確認，目前**沒有**證據；「不適用」＝站上沒有該功能。

| 準則 | 現況 | 依據／說明 |
| --- | --- | --- |
| 2.4.11 焦點不被遮蔽（最低） | 待人工稽核 | 手機有固定底部 tab 列（`.c-tabbar`）；未做逐頁鍵盤走查，尚無 `scroll-padding` 保證。axe 判不出 |
| 2.5.7 拖曳動作 | 符合（不適用為主） | 站上沒有必須拖曳的功能；後台附件區的拖放上傳另有「選擇檔案」按鈕替代 |
| 2.5.8 目標尺寸（最低） | 部分符合 | 輪播圓點、/data/ 端點連結已補到 24px（本輪）；其餘按鈕多為 36–44px。內文中夾雜的行內連結屬規範例外；自訂 HTML 內容仍須人工檢查 |
| 3.2.6 一致的求助 | 符合（程式碼）／待人工確認 | 頂端工具列（無障礙、網站導覽、防疫專線 1922）與頁尾聯絡區在每頁同一版面元件輸出，位置一致 |
| 3.3.7 避免重複輸入 | 待人工稽核 | 站上表單多為單頁（智慧查詢、聯絡信箱預覽）；人才招募模擬報名跨步驟，需確認 |
| 3.3.8 無障礙的驗證 | 不適用（原型） | 原型後台為示範登入（模擬帳號）；正式環境走機關 SSO＋MFA，設計見 [admin-auth.md](admin-auth.md)，上線前須依本準則複查 |
| WCAG 2.1 既有 AA 項目（對比、鍵盤、標題、地標、語言、1.4.10 重排等） | 自動檢測可判定的部分符合 | 見第 5 節；螢幕閱讀器朗讀品質、圖片 alt 的內容是否「有意義」仍待人工稽核 |

**axe 的限制：** 自動工具大約只能抓到三成到五成的問題。通過 `npm run a11y` ≠ 符合規範；它是「不退步」的底線，不是稽核報告。

### 4.1 第四十輪（#83）修掉的殘留項

線上 axe（25 路徑 × 桌機／手機）剩下兩類 moderate：`/ask/?q=登革熱` 的 heading-order、`/admin/` 與 `/admin/publish/` 的 region。這一輪的處理：

| 發現 | 位置 | 修法與理由 |
| --- | --- | --- |
| heading-order：`/ask/?q=登革熱` | `src/client/answer/render.js` 的 `situationCards()`（疫情卡） | 實際跳級的是**疫情卡的標題 `<h3>`**：它由 JS 在答案區塊**之前**產生，前面只有 sr-only 的 `<h1>`，所以是 h1→h3。改成 `<h2>`（卡片本身是帶 `aria-label` 的獨立區塊，與下方「回答」同層）；`answer.css` 的 `.c-answer-sit h3` 規則同步改 h2，並補上標題內連結的樣式（原本靠 `.c-sit-card h3 a`）。來源清單（h3）、「接下來可以」（h3）、「你可能也想知道」（h3）都接在答案 h2 之後，本來就合法。**限制**：這些 h3 如果在沒有 h2 的答案（例如只有 actions 沒有句子的情況）出現仍會跳級；目前沒有這種答案，若新增要同步處理。 |
| region：`/admin/`、`/admin/publish/`、`/admin/review/` | `src/templates/admin/_layout.mjs` 的 `.adm-demo` | 原本是地標之外的 `<div role="note">`（`role="note"` 不是地標）。改成 `<aside class="adm-demo" aria-label="示範說明">`，成為 complementary 地標；位置與外觀不變（仍在導覽列與 `<main>` 之間）。沒有放進 `<header>`，是因為它在 DOM 順序上位於 `<nav>` 之後，放進 header 會改變閱讀順序。`<nav class="adm-nav">`、`<footer class="adm-foot">`、`<main>` 本來就是原生地標元素。 |
| target-size（serious）：`/ask/?q=登革熱` 的來源卡 | `answer.css` `.c-source-card__body .c-deflist dd a` | 新增掃描 `/ask/?q=` 之後才露出來的：來源卡 `<dd>` 裡獨立成行的連結高約 20px、與下一行只隔 6px，不符 WCAG 2.5.8 的 24px。加 `display:inline-block; min-height:24px; line-height:24px`。**以前沒被發現是因為掃描清單裡沒有載入答案後的 `/ask/` 畫面**（空的 `/ask/` 沒有來源卡）。 |

前後數字（本機 `BASE_PATH='' PAGEFIND=off` 建置、`npm run a11y`，掃 22 頁 × 2 視窗；全文搜尋「有結果」那一頁需要 Pagefind 索引，沒有索引時列為略過）：region 6 筆（3 頁 × 2 視窗）→ 0；serious（target-size）1 筆 → 0；heading-order 本機 axe 沒有重現（線上有），但標題結構傾印 h1→h3 → h1→h2，依 axe 的規則這就是會被標的位置。

## 5. 怎麼跑自動檢測

```bash
BASE_PATH='' node scripts/build.mjs     # 先建置（腳本本身不建置；沒有 dist/ 會直接報錯）
npm run a11y                            # 對 dist/ 跑 axe-core
```

- 範圍：（第四十輪起含 `/ask/?q=登革熱`，載入答案後才掃，`#answer[aria-busy=false]`）首頁、疾病頁、疾病列表、疫苗、旅遊、新聞、Q&A、智慧查詢、疫情、資料、專業版、後台首頁、後台上架、/en/、/vi/、核心教材文件頁（第二十八輪，長文件版面＋學習目標）（dist 內沒有的會略過並列出）；每頁在桌機 1280px 與手機 320px 各掃一次。
- 規則集：`wcag2a, wcag2aa, wcag21aa, wcag22aa, best-practice`。
- 結果：**serious／critical → exit 1**（擋合併）；moderate／minor 只列警告，**但會輸出數量與規則別次數**（報告開頭、終端機最後一行 `[a11y] 阻擋 N、警告 M：region×…`，以及 `A11Y_JSON=檔名` 的機器可讀摘要）；CI 的 PR 留言「無障礙檢測」列會顯示「另有 N 項 moderate／minor 警告，不擋合併」，不會因為不擋就悄悄累積；手機 320px 出現橫向捲動也算失敗（1.4.10）。另輸出 Markdown 摘要（`A11Y_REPORT=檔名` 可另存；在 GitHub Actions 自動寫進 job summary）。
- 瀏覽器：`CHROME_BIN` 環境變數優先；其次 `PLAYWRIGHT_BROWSERS_PATH`（預設 `/opt/pw-browsers`）內的 chromium；都沒有就用 Playwright 內建（`npx playwright install chromium`）。
- 用其他目錄：`DIST_DIR=/tmp/x npm run a11y`。建置時若有 `BASE_PATH`，執行檢測時要設同樣的 `BASE_PATH`。
- 第七十五輪：每頁每視窗 axe 之後再做一次**焦點遮蔽走查**（WCAG 2.4.11），焦點元件被固定／黏性元件完全蓋住算阻擋、部分蓋住算警告（`focus-obscured-partial`）；細節見第 12.4 節。第七十六輪起部分蓋住也算阻擋（本站選做 AAA 的 2.4.12），並多走一趟從頁尾往回的 Shift+Tab（第 13.3 節）。
- 第七十五輪：另有不開瀏覽器的**檢測碼預檢** `npm run a11y:tw`（新版網站無障礙規範附件一的 A／AA 級檢測碼，掃 dist 全部 HTML 與自有 CSS），見第 12 節。
- CI：`.github/workflows/content-pr.yml` 直接掃 PR 的預覽建置（第五十六輪起不再另建 `BASE_PATH=''` 的一份；`BASE_PATH` 設成與預覽相同，腳本的靜態伺服器會去掉前綴，見 [deploy.md](deploy.md) §28.5），只在含程式或文件變更的 PR 跑（純內容 PR 沒改版型，略過）；結果列在 PR 留言表格「無障礙檢測（axe）」，並列入「能不能合併」的條件。

## 6. 手機語言選單（#33）

- 桌機（>720px）維持頂端橫排語言列（`nav.langs.langs--inline`）。
- 手機（≤720px）橫排改成單一按鈕 `<details class="langmenu"><summary>（地球圖示）語言／Language</summary>…`（第七十五輪起地球圖示是 `aria-hidden` 的 SVG，不再是表情符號，見第 12 節），展開後七種語言各用自己的語言標示（`lang`／`hreflang` 屬性齊全），不需 JS；≤959px 的「選單」面板底部也有同一組語言。
- 為什麼用 `<details>`：原生支援鍵盤與螢幕閱讀器（朗讀「已展開／已收合」），不必另寫 JS 與 `aria-expanded`。
- **暫不做、列為建議**：依瀏覽器 `Accept-Language` 自動提示切換語言。理由：原型不是每頁都有七語（只有 reviewed 的才有），自動提示可能把人導到沒有該頁的語言；要做應先確認各語言涵蓋率與是否記住使用者選擇（需 cookie 告知），所以延後。

## 8. 主選單子選單（第四十七輪）

三個有面板的主選單項目（傳染病、疫苗、出國與入境）旁有 `<details class="c-nav__dd" data-nav-dd><summary class="c-nav__more">`，展開 `.c-nav__panel`。設計理由見 [navigation.md](navigation.md) 第 5 節；注意現行 cdc.gov.tw 選單結構是推斷，非直接確認。

**無障礙名稱從哪來：** summary 的可見內容只有 chevron 圖示（`aria-hidden="true"`），名稱來自裡面的 `.sr-only` 文字「展開「疫苗」的子選單」（i18n `nav.more`，七語）。**不在 summary 上用 `aria-label`**，因為各讀屏軟體對 summary 的 `aria-label` 支援不一致，用可見文字節點最穩。summary 也不加 `role` 或 `aria-expanded`：`<details>` 原生就暴露「已展開／已收合」。面板是 `role="group"` 加 `aria-label`（`nav.panel.label`），內部小標用 `<p>`，不用標題，避免頁首出現會讓標題階層跳級的標題。

| WCAG | 對應 | 做法 |
| --- | --- | --- |
| 1.4.13 hover 或焦點出現的內容 | 不適用，但說明 | 面板由點擊開啟，不由 hover 或焦點觸發，所以「可關閉、可停留、不消失」三條件不適用；CSS 禁止任何 `:hover` 開面板的規則（測試掃 base.css）。這也是不用 hover 的理由之一：hover 式 mega menu 最常在這條失分 |
| 2.1.1 鍵盤 | 通過 | summary 原生可 Tab 聚焦、Enter／Space 開合；面板內都是一般連結，Tab 依序可達 |
| 2.1.2 沒有鍵盤陷阱 | 通過 | 面板不是 modal，不鎖焦點；Tab 離開面板，`focusout` 就收合（只在焦點確定移到面板外時才關，點面板內純文字由點外面的判斷處理，不會誤收）；Esc 關閉並把焦點回到 summary |
| 2.4.3 焦點順序 | 通過 | 面板的 DOM 緊接在對應的主選單連結與 summary 之後，Tab 順序＝視覺順序；桌機面板絕對定位但 DOM 順序不變；手機手風琴本來就在文件流中 |
| 4.1.2 名稱、角色、值 | 通過 | 角色與展開狀態來自 `<details>/<summary>` 原生語意，名稱來自 `.sr-only` 文字，不自訂 ARIA，避免與原生語意衝突 |
| 2.5.8 目標尺寸（最小） | 通過 | summary 桌機 36×44、手機 48×48（絕對定位在該列右側，連結右側留 56px padding 不被蓋住）；面板連結桌機 min-height 40px、手機 44px |

驗證：`tests/round47-nav-panels.test.mjs` 檢查 summary 結構（`.sr-only`、無 `aria-label`／`aria-expanded`／`role`）、面板內無標題、ui.js 含 Esc 與 `focusout` 處理，並用 Playwright 在 1280px 與 390px 實測開合、Esc 焦點、點外面關閉、面板不被裁切，以及在 1280px 開傳染病面板後用 axe 掃描整個首頁無 serious／critical。尚未用 NVDA／VoiceOver 實測，列入第 7 節的人工走查。

## 9. 人工走查腳本與標章申請準備（第四十八輪，Issue #104）

給資訊室與承辦同仁。第 7 節列的「尚未處理」有三項只有人能做：螢幕閱讀器實測（NVDA＋Chrome、VoiceOver＋iOS Safari）、2.4.11 焦點不被遮蔽、3.3.7 重複輸入。這一節是可以照著做的腳本、要填的表，以及申請無障礙標章要準備的證據。**為什麼要人工做：** axe 這類工具只能檢查標記「有沒有」，不能判斷「讀起來順不順」。同一段正確的 HTML，螢幕閱讀器可能朗讀成毫無意義的一串；標章的檢測單位與評審也只認人工檢測紀錄，不認 CI 綠燈。

## 10. 放大文字與窄螢幕不橫向捲動、頁籤標題層級（第四十八輪，#98、#99）

**問題一：放大文字或手機窄螢幕時整頁會左右拖。** 實測（Playwright，`document.documentElement.scrollWidth`）：

| 情境 | 頁面 | 修前 | 修後 |
| --- | --- | --- | --- |
| 320 px | `/procurement/` | 381 | 320 |
| 320 px | `/careers/` | 378 | 320 |
| 文字 200%／390 px | `/procurement/` | 694 | 390 |
| 文字 200%／390 px | `/careers/` | 655 | 390 |
| 文字 200%／390 px | `/ask/` | 553 | 390 |
| 文字 200%／390 px | `/diseases/influenza/` | 565 | 390 |
| 文字 200%／390 px | `/data/`、`/subscribe/`、`/en/`、`/vi/`、`/en/subscribe/` | 431／481／457／477／494 | 390 |

原因都是同一類：flex／grid 子項目有「最小寬度」（內容寬度）而不是可縮的，放大文字後最小寬度比螢幕還寬。處理原則（之後新增版面請照做）：

- flex 子項目要能縮：`min-width:0`，並且 `flex-basis` 用 `rem` 或 `min(…,100%)`，不要用固定 `px`（`.c-askbox` 的輸入框原本 `flex:1 1 200px`，放大後與按鈕排不下又不換行）。
- grid 欄用 `minmax(0,1fr)`、`minmax(min(14em,100%),1fr)`，不要用 `1fr`（等於 `minmax(auto,1fr)`，會被內容撐開）或固定 `14em`。
- 膠囊、標籤的 `white-space:nowrap` 在「會放長文字」的地方要拿掉（職缺卡右側欄的截止標籤、翻譯狀態標籤、chips 列）。
- 長連結、單號、英文長字：容器加 `overflow-wrap:anywhere`。

**怎麼防止退步：** `npm run a11y` 新增視窗「文字 200%／390」（390 px 寬、根字級 200%），與原本的 320 px 一樣檢查橫向捲動，**算阻擋項**（和 serious／critical 同級）；`PAGES` 加了 `/procurement/`、`/careers/`。結果表多一欄「視窗」。

**問題二：`/procurement/`、`/careers/` 標題層級跳級（h1 → h3）。** 頁籤面板裡有一個 `<h2 class="c-tabs__print">` 當「這個面板是什麼」，但螢幕上是 `display:none`，輔助科技與 axe 都看不到它，只看到 h1 之後直接出現職缺／標案的 h3。改成**螢幕上只給螢幕閱讀器看**（和 `.sr-only` 同樣的 clip 寫法），沒有 JS 與列印時仍是一般可見的 h2。這個 class 也用在 `/notices/`、疾病頁的頁籤，一併修好。`display:none` 的元素不會被讀出來，要「視覺上不顯示但要讓輔助科技讀到」就不能用它。

驗證：`tests/round48-ui.test.mjs`（CSS 規則、每個面板 h3 之前有 h2、a11y 腳本設定）＋ `npm run a11y`（含新視窗與新頁面，0 阻擋、0 警告）。

**HM2310200C 第七十六輪補完、改為擋合併**（業主核可）。做法分兩層：

1. **模板層（知道「這是退回」的地方）**：`_partials.mjs` 新增 `Lx(ctx, item, field)`（與 `L()` 取同一個值，另外回傳語言：`i18n[lang]` 沒有這一欄、退回來源語言時是 `zh-TW`）、`langOf()`、`leadOf()`。十二個模板的頁首說明、文件家族標題、職缺類別與採購方式膠囊、單位職掌清單、旅遊國家頁的區域名稱、疾病頁年度圖表，在外語頁退回中文時把 `lang="zh-TW"` 標在承載元素上。疫苗時程圖的 SVG `<title>` 不能包 `<span>`，外語頁沒有英文標籤時改用列名（頁面語言）。這一層收掉約 1,780 筆。
2. **整頁安全網（`scripts/lib/a11y-text.mjs` 的 `markFallbackLang()`，`pages.mjs` 每頁輸出前）**：剩下散在幾十個模板裡的中文片段（單位名稱、表格儲存格、i18n 變數裡的中文值、Markdown 本文…）由這裡補。外語頁（日文頁除外：日文本來就用漢字）從第一個漢字到最後一個漢字或全形標點算一段，中間只容許空白、數字、半形標點與全大寫縮寫（MMR、COVID-19），遇到小寫英文字就斷開；整段就是承載元素的全部文字時，把 `lang` 加在那個元素上（不改 DOM 結構，行內連結的判斷不受影響），否則就地包 `<span lang="zh-TW">`。`<head>`／`<title>`、script、style、code／pre 與屬性值不動；`<option>`、`<textarea>`、SVG 裡不放 span（只在整段同一語言時加在元素上）。反向（中文頁）：整段沒有漢字、連續 4 個以上英文字的文字標 `lang="en"`（`sourceLang:'en'` 內容的標題、英文國名、外文文獻）。建置記錄一行 `[pages] 不同語言片段補 lang…：N 處`，本輪約 3,480 處。

**專有名詞例外**：中文頁上 3 個字以下的英文（WHO、Taiwan CDC）本來就不判；其他確定不該標的專有名詞，在承載元素加 `data-a11y-propernoun`，`a11y:tw` 與安全網都會略過（目前全站沒有用到）。安全網是第二層：新模板遇到「退回中文」時仍請用 `Lx()`／`langOf()` 在模板裡標，安全網只是讓漏掉的不會上線。

### 12.4 2.4.11 焦點不遮蔽：手機 tabbar 把焦點整個蓋住

**發現**：評估腳本在 390 px 手機視窗按 Tab 走查，固定在底部的 `.c-tabbar` 在 5 個頁面把取得焦點的元件**完全蓋住**（/play/ 測驗卡連結、/about/leadership/ 的「署長職掌與施政重點」「署長信箱」、/en/search/ 與 /id/search/ 的「Advanced filters」），另 3 頁部分蓋住。原因：`body{padding-bottom:var(--tabbar-h)}` 只讓**內容**不被蓋，瀏覽器把焦點元件捲進視窗時仍對齊視窗底邊，剛好落在 tabbar 後面；`html` 只有 `scroll-padding-top`，沒有 bottom。這一條原本在第 7 節列為「待人工走查」，現在有自動化證據了。

**修法**：手機媒體查詢（≤720 px，tabbar 出現的同一段）加 `html{scroll-padding-bottom:calc(var(--tabbar-h) + 8px)}`。往回走（Shift+Tab）時，頂端黏性的疾病頁頁籤列 `.c-hubnav` 與桌機版答案頁提問列 `.c-askpage__bar` 也會蓋住捲上來的焦點（Shift+Tab 走查各量到 3–9 次遮蔽），所以有這兩個元件的頁面用 `html:has(…)` 把 `scroll-padding-top` 加到它們的高度（用 rem，放大文字時跟著變）；答案頁提問列在 959 px 以下是 static，那裡改回 16 px。

**防止退步**：`npm run a11y` 每頁每視窗在 axe 之後按 Tab 最多 80 下，取焦點元件**在視窗內那一塊**的 5×5 個點，用 `elementFromPoint` 打點：

- 25 個點全部打到「別的、位在 `position:fixed`／`sticky` 祖先底下」的元素 ⇒ **阻擋**（「2.4.11 焦點被固定元件完全遮蔽」表，算進 `[a11y] 阻擋 N`）；
- 部分點被蓋 ⇒ 警告（`focus-obscured-partial`，算進 `[a11y] … 警告 M`，PR 留言照舊顯示規則別次數）。**第七十六輪起改為阻擋**（2.4.12，見第 13.3 節）。

驗證：把 `scroll-padding-bottom` 從建置後的 CSS 拿掉再跑一次走查，/play/、/about/leadership/、/careers/、/diseases/dengue/ 各抓到 6–10 個完全遮蔽的元件（比評估腳本的 5 頁多；差別在走查前先把 `scroll-behavior` 設成 `auto`；評估腳本沒有，量到的是平滑捲動途中的位置，所以修正後重跑它仍報 4 頁，關掉平滑捲動後是 0，見 12.5 末）；放回去後 0。代表頁加了 `/about/leadership/`。走查只往下按 Tab、只走代表頁；Shift+Tab 與更多視窗仍屬人工走查（第 9.2 節）。

### 12.5 行內連結的描述性 title（HM1240401C，業主決定 A 案）

**規範的要求**：「連結要有文字；若連結前後尚有其他內容，另需 `title` 屬性」。這是台灣政府網站每個 `<a>` 都有 title 的由來。站上 3,308 頁共 39,510 個行內連結沒有 title（疾病頁的「CSV／JSON／API」、「看趨勢與地圖 →」、頁尾、表格裡的單位連結…）。

**業主（Yulun）的決定：A 案——行內連結自動補「描述性」title。**

- 「行內連結」的定義：`<a href>` 的父元素裡，除了連結還有非空白文字，或有字的行內元素（`span`、`strong`、`time`…）；父元素是文字段落類（`p`、`li`、`td`、`dd`…）時，並排的其他連結也算（例如頁尾 `<p>` 裡並排的「1922」「0800-001922」）。單獨佔一個清單項目、卡片的連結，以及 `<div>`／`<nav>` 裡一排並列的選單、按鈕列，**不算**——那是 AAA 的 HM3240900C（每個連結都要 title），不是目標。SVG 裡的連結（/travel/ 世界地圖、/vaccines/schedule/ 時程圖）不補：它們的名稱來自 `<title>` 子元素，SVG 也沒有 `title` 屬性；Freego 是否另外要求，對照時確認。
- title 的格式：`連結文字：上下文`。上下文依序取「連結之前最近的標題（h1–h6）」→「頁面標題」→「站名」，取第一個不等於、也不被包含在連結文字裡的。外部網站再加「（外部網站：host）」；PDF、CSV、JSON 等下載檔前面加「下載 格式：」。字詞（「下載」「外部網站」「：」與英文的「 – 」）來自 i18n，依當頁語言。
  例：`下載 CSV：資料：預防`、`WHO：預防（外部網站：www.who.int）`、英文頁 `Influenza – Current outbreaks`。
- **title 一定包含可見的連結文字**（WCAG 2.5.3 名稱含標籤：語音操作的人說出看到的字就點得到），而且不會只等於連結文字。
- 已經有 title 的連結不動。資料集來源卡的「CSV／JSON／API」與疾病頁「看趨勢與地圖 →」在模板裡直接給更好的 title（`下載「登革熱每日確定病例統計」CSV`、`看趨勢與地圖：登革熱`），不靠自動產生。

**實作在哪一層**：

1. **Markdown 渲染器**（`scripts/lib/markdown.mjs` 的 `md()`）：段落、清單、表格裡的連結，用「這份 Markdown 裡連結之前最近的標題」當上下文。`md()` 的二十幾個呼叫端都不傳語言，所以 `pages.mjs` 渲染每一頁前用 `setMarkdownPage()` 設定當頁的 `t()`；沒設定時（單元測試、閘道預覽）不補，輸出與以前相同。片段裡沒有標題可用的連結留給下一層。
2. **整頁安全網**（`scripts/lib/pages.mjs`，每頁輸出前）：同一個函式 `inlineLinkTitles()` 對整頁再套一次，這時知道頁面標題。為什麼要有這一層：行內連結散在五十幾個模板（頁尾、新聞列表、表格、說明文字…），逐一手改不切實際，而且新模板不會記得；安全網讓新模板自動符合。它用 htmlparser2 解析、只在開始標籤的 `>` 前插入 `title`，不重新序列化 HTML，其他位元組不變。
3. JS 產生的連結（答案頁、搜尋結果、訂閱頁的訂閱網址表）不在建置時，`a11y:tw` 也看不到；這部分留給 Freego 對照時確認。

**用評估腳本重跑的結果**（44 個代表頁、Playwright 載入並執行 JS 後量 DOM）：行內連結沒有 title **672 → 225**（剩下的 203 個是上面說的 SVG 地圖與時程圖連結，其餘 22 個是 JS 產生的）；表情符號沒有 title **112 → 0**；表格標題格沒有 scope **6 → 1**（`/developers/` 由 `src/client/pro.js` 產生的 openapi 端點表，已補 scope）；AAA 的「每個連結都要 title」4,754 → 4,184（不是目標）。評估腳本的焦點走查在修正後仍回報 4 頁「完全遮蔽」，把它的走查改成先關平滑捲動後是 0 頁、部分遮蔽也是 0——它量到的是平滑捲動途中的位置（12.4）。

**取捨（為什麼國際實務通常不這樣做）**：螢幕閱讀器在某些設定下會把 title 和連結文字各唸一次，多唸的部分是雜訊；axe 的 best-practice 也把「與連結文字重複的 title」視為不必要。我們的緩解：title 是**描述性**的（補上下文、外站、下載格式，而不是重複連結文字），多唸的那一段至少是新資訊；而且只補行內連結，選單與卡片不加。代價接受的理由：2026-11-30 起依新版規範檢測，Freego 判不合格的項目會讓標章申請卡住；被判的是全站每一頁。決策與沒選的做法見 [architecture-decisions.md](architecture-decisions.md) 第 60 節。

### 12.6 `npm run a11y:tw` 怎麼跑、怎麼讀

```bash
node scripts/build.mjs          # 先建置（腳本本身不建置）
npm run a11y:tw                 # 掃 dist 全部 HTML 與 dist/assets 的自有 CSS（約 5 秒）
A11Y_TW_JSON=/tmp/tw.json npm run a11y:tw   # 另存機器可讀結果
```

- 輸出：依檢測碼分組的 Markdown 表（等級、要求、判定、數量、頁數），每個有發現的檢測碼列前 5 筆（頁面＋片段）；終端機最後一行 `[a11y:tw] 不合格 N、警告 M`。A／AA 級不合格 ⇒ exit 1。在 GitHub Actions 會附加到 job summary。
- 範圍：`DIST_DIR`（預設 dist/）裡的 HTML；PR 預覽（dist/preview/）、Pagefind 與 vendor 的第三方檔不算。
- 限制：不開瀏覽器，所以看不到 JS 產生的畫面與 CSS 計算後的樣式（例如元素是否被隱藏）。這部分由 `npm run a11y`（axe＋焦點走查）負責。
- **為什麼也在 `test:content` 裡**：本輪發現的表格缺 scope、表情符號缺 title 都是從內容（Markdown／JSON）進來的，而純內容 PR 不跑瀏覽器檢測。`tests/a11y-tw-codes.test.mjs` 有 dist 就掃 dist，沒有（CI 的純內容 PR 在建置之前跑 `test:content`）就在記憶體裡渲染全站再掃，所以內容 PR 一樣會被擋下（[deploy.md](deploy.md) §28.4）。代價是 `test:content` 本機 4 核由約 18 秒變約 27 秒，仍在 30 秒預算內。
- 寄出的電子報 HTML（`src/client/subscribe-rules.js` 的行內 `font-size:13px`）不是網頁，不在檢測範圍。

## 13. AAA 的取捨與本站選做項目（第七十六輪，2026-11-27）

> 給資訊室與承辦同仁。一句話：**無障礙標章的目標仍是 AA**；下面幾項 AAA 是「做得到、而且對讀者有用」才選做，逐項宣告、逐項有自動檢查，不代表全站宣稱 AAA。

### 13.1 為什麼不以全站 AAA 為目標

W3C 的〈Understanding Conformance〉明白寫：不建議把 AAA 當成整個網站的一般性要求，因為有些內容本質上做不到 AAA。對本站而言，做不到的地方很具體：

1. **台灣規範的兩個 AAA 檢測碼與本站設計衝突**（附件一的 AAA 級軟體檢測碼，Freego 會判）：
   - **CS3140800C**：單一樣式表不得指定主內容的前景色與背景色，除非網站提供使用者切換配色的功能。本站的品牌綠、狀態色（上升／高峰／下降）、警示框底色都由樣式表指定，而且狀態色是資訊的一部分。要過這條，得另做一套「使用者配色切換」並讓每個元件在任何配色下都看得懂。
   - **HM3240900C**：**每個**連結都要有 `title`。第七十五輪評估的 44 個代表頁上，5,098 個連結有 4,754 個沒有 title（補完行內連結後仍有 4,184 個，都是選單、卡片、按鈕列這類不在句子裡的連結）。全部補上的結果是螢幕閱讀器在常見設定下把 title 和連結文字各唸一次；第 12.5 節的 A 案只補「行內連結」並要求 title 帶新資訊，就是為了不走到這一步。
2. **1.4.6 加強對比（7:1）會改掉品牌色**。本輪用 tokens.css 量：15 組常用的文字／底色裡有 11 組低於 7:1，例如次要文字 `--ink-3` 對白底 6.09、對暖白 5.63；綠 600 底上的白字 5.31；疫情狀態色（上升 5.38、高峰 5.33、下降 5.77、平穩 5.85）；警示 6.44、資訊 6.98。AA（4.5:1）全數通過；要到 7:1，狀態色與次要文字都得加深，等於重訂品牌色票。
3. **每次發布都要付的內容成本落在各單位承辦**：
   - 1.2.6 手語：每支預錄影片都要手語翻譯；
   - 1.2.7 延伸口述影像：畫面資訊多、停頓不夠的影片要另做可暫停的口述版；
   - 3.1.5 閱讀程度：超過國中程度的內容要另寫易讀版——病例定義、檢驗規範、法規、專業教材本質上就在這個程度以上；
   - 1.4.9 不用文字圖片：宣導海報與資訊圖表本身就是文字圖片（我們已要求附全文，但「不用」做不到）。
4. **2.5.5 目標尺寸 44 px 若要全站一律**：/travel/ 的 505 個國家膠囊與 SVG 世界地圖的國家連結（小國只有幾個像素）都得重做；本輪只在手機版做，地圖以等價清單豁免（13.3）。
5. **標章抽測與撤銷的風險**：標章是申請後抽測、可撤銷的。宣稱 AAA 後，二十幾個單位每次發布都要守住手語、易讀版、7:1 這些條件，只要一次發布沒守住，就是「聲明不實」而不只是「某頁有瑕疵」。宣稱 AA、逐項標示選做的 AAA，風險可控。

做法（`base.css` 最後一段，全部在 `@media (max-width:720px)` 裡，桌機版面不動）：
- 按鈕、summary、表單欄位、`role=button`、可聚焦元素：`min-height／min-width: 2.75rem`；
- 單獨成塊的連結（清單項目、標題裡唯一的連結）：`display:inline-flex; align-items:center; min-height:2.75rem`。判斷「單獨成塊」用 `:only-child:not([title])`：句子裡的行內連結在建置時都已補上 title（第 12.5 節），所以這個選擇器剛好把它們排除；
- 規則用 `:where()` 寫成權重 0，元件自己設的 `display` 一律優先；第七十五輪設成 24 px 的幾個元件（頂端工具列、疫情卡的地圖連結…）另外加權重覆寫；
- 疫情狀態標籤（`role=button` 的膠囊）用上下透明邊框把點擊區撐到 44 px，看得到的膠囊維持原大小；輪播圓點的點擊區由 24 px 改 44 px（看得到的圓點仍是 12 px）。

**例外（已記錄）**：/travel/ SVG 世界地圖的國家連結不放大——同一頁有等價的國家清單與查詢欄（WCAG 2.5.5 的「等價」例外）。

**3.1.4 縮寫**：縮寫表＝詞彙主檔（`content/master/glossary.json`）裡 `en` 或 `aliases` 長得像縮寫的詞（HIV、TB、BCG、MERS…），全稱用主檔裡**當頁語言**的譯名（去掉結尾的「（TB）」）；譯名本身含縮寫（英文的「HIV infection」、「MMR vaccine」）就不是全稱、不標。主檔沒有或譯名不是全稱的少數幾個（MMR、COVID-19、HPV、RSV、PCR、RT-PCR、WHO）在 `abbr.mjs` 的 `ABBR_EXTRA` 補中英文全稱；其他語言頁只用主檔譯名。CDC 不標（站上也可能指美國 CDC）。只在 `<main>` 裡的 p、li、td、dd、dt、blockquote、figcaption、caption 的文字裡找；標題、連結、按鈕、code／pre、SVG、`<nav>` 與屬性值不動；每頁每個縮寫只標第一次。只在「已經有字的文字節點」裡切出 `<abbr>`，所以第 12.5 節「行內連結」的判斷不受影響（測試比對包之前、包之後的檢測碼結果相同）。

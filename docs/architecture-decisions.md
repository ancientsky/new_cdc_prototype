# 為什麼這樣做：架構決策紀錄

> 給誰看：要評估、接手或擴充這個原型的人。每一項決策都寫「決定、理由、代價、什麼時候該重新考慮」。
> 原始約定見根目錄 [ARCHITECTURE.md](../ARCHITECTURE.md)。

## 決策總表

| # | 決策 | 一句話理由 |
| --- | --- | --- |
| 1 | Git 當 CMS | 內容改動天生有審核、紀錄、回溯 |
| 2 | 靜態生成 | 便宜、快、安全、好備援；治理計算全放建置階段 |
| 3 | 抽取式優先的答案引擎 | 官方機關不能讓 AI 自創說法 |
| 4 | LLM 只做可選、BYOK | 不綁供應商，不替人民付費，不經本站伺服器 |
| 5 | 治理在建置時計算 | 規則寫一次，頁面、API、AI 結果一致 |
| 6 | 每日排程抓官方資料 | 沒有後端也能有新鮮的旅遊疫情與目錄 |
| 7 | 失效版本用 noindex＋301，不用 robots.txt | 爬蟲被擋就看不到 noindex，舊版反而更難被清除 |
| 8 | 版本用獨立檔案表示 | 舊版不被覆蓋，才有版本鏈與異動對照 |
| 9 | 狀態由人工發布 | 疫情的四級狀態是專業判斷，不是模型輸出 |

## 1. Git 當 CMS

**決定：** 內容與資料以 JSON 檔存在 `content/`，改動走 Pull Request，CI 驗證後合併即發布。
**理由：** 機關最怕「誰在什麼時候改了什麼」說不清楚。Git 免費提供作者、時間、差異、審核與回溯；PR 的複核者就是流程中的覆核關卡；CI 把必填欄位、參照完整性和評估集變成機器強制，而不是靠公文提醒。後台頁面（`/admin/`）只是這個流程的操作介面，匯出的 JSON 才是交付物。
**代價：** 非技術同事需要後台介面協助，不能直接編輯檔案；大量圖片與影片不適合放在 Git。
**何時重考慮：** 同時編輯者多到 PR 衝突頻繁，或需要即時發布（分鐘級）時，可在 Git 前加一層有權限控管的編輯器，但資料仍以 Git 為準。

## 2. 靜態生成

**決定：** `npm run build` 把內容算成 HTML、`.md`、`v1/*.json`、`sitemap`、`llms.txt`，部署到 GitHub Pages（純靜態）。
**理由：** 疾管署網站在疫情期間流量會暴增，靜態檔由 CDN 供應最耐壓；沒有資料庫與應用伺服器，攻擊面最小；任何時間點的網站都能完整重建與還原。對 AI 爬蟲而言，靜態 HTML 加機讀版也最友善。
**代價：** 內容變更要等建置（約數分鐘）才上線；無法有伺服器端個人化——所以個人化（角色、訂閱）放在瀏覽器 localStorage。
**何時重考慮：** 需要即時登入個人化、即時通知寄送時，加獨立服務，不改變靜態主體。

## 3. 抽取式優先

**決定：** 預設答案引擎不生成新句子：把白名單內容切成「答案單元」，用中文 bigram 加詞彙同義詞與 BM25 檢索，直接挑出原文句子，每句附來源編號。
**理由：** 公部門的 AI 回答若有一句沒有依據，就是一次公信力事故。抽取式讓「每句都有出處」成為結構性保證，而不是靠提示詞祈禱。同時它不需要金鑰、不花錢、在瀏覽器就能執行，同一份程式碼（`src/client/answer/core.js`）也能在 Node 跑評估集。
**代價：** 答案不如生成式流暢，跨文件整合能力弱。
**緩解：** 提供 LLM 模式，但加上後檢（見下）。

## 4. BYOK LLM

**決定：** 使用者可自行輸入 Anthropic API 金鑰，存瀏覽器 localStorage，由瀏覽器直接呼叫；頁面標示供應商與模型。系統提示限制只能依檢索片段作答，輸出 `{sentences:[{text, cite:[chunkId]}]}`；後檢刪除沒有 cite 或 cite 不在檢索片段內的句子，全部被刪就退回抽取式。
**理由：** 機關不必先決定採購哪家模型、不替使用者承擔 token 費用、對話不經過本站伺服器；後檢確保「模型不能說片段以外的話」。
**代價：** 一般民眾不會用；金鑰存在瀏覽器有被惡意擴充功能讀取的風險，所以只當進階功能且在介面上提醒。
**何時重考慮：** 機關有正式採購的模型服務與資安審查後，改由受控的後端代理，並維持相同的後檢。

## 5. 治理在建置時計算

**決定：** 下次審閱日、逾期、失效版本、衍生內容待辦、白名單資格、翻譯是否過期、KPI，全部由 `scripts/lib/governance.mjs` 在建置時從欄位推導，掛回 `item.gov`；模板與前端只讀不算。
**理由：** 規則只寫一份，網頁、API、`.md`、JSON-LD、AI 索引才不會互相矛盾。時間相關的狀態（逾期）靠每日排程重建自動更新。治理規則有 `tests/` 的單元測試，每條至少一個案例。
**代價：** 狀態最快每日更新一次；要立即生效（如 AI 暫停）需要走緊急 PR。
**何時重考慮：** 若需要分鐘級狀態，可把「暫停」這類少數開關改成執行期讀取的小檔案，其餘不變。

## 6. 每日排程抓官方資料

**決定：** GitHub Actions 每日 03:00 UTC 執行 `npm run fetch`，抓旅遊疫情、國家等級、CKAN 資料目錄到 `data/snapshots/`，每檔記錄來源與抓取時間（provenance）；抓不到就沿用既有快照，不讓建置失敗。
**理由：** 沒有後端也能有新鮮資料；快照讓建置可重現；失敗降級讓外部服務中斷不會拖垮網站。
**代價：** 資料最多延遲一天；若來源改格式，快照會停在舊資料——因此資料集有「時效逾期」待辦與 `provenance.mode` 標示，不會悄悄過期。

## 7. 失效版本用 noindex 與 301，不用 robots.txt

**決定：** 被取代的文件頁輸出 `<meta name="robots" content="noindex">`，退出站內搜尋索引與 sitemap，並在 `redirects.json` 記一筆 301；`robots.txt` 只擋 `/ask/` 和 `/admin/`。
**理由：** `robots.txt` 擋住的是「抓取」，不是「收錄」。爬蟲被擋就讀不到頁面上的 `noindex`，網址仍可能因外部連結留在搜尋結果裡。要讓舊版從搜尋與 AI 檢索消失，必須讓爬蟲能讀到 noindex 與導向。
**代價：** 舊版頁面仍可被直接連到（這是特性：專業人員需要查閱歷史版本），所以頁首必須有紅色橫條。

## 8. 版本用獨立檔案表示

**決定：** `doc.mmr-recommendation.2019-05-14` 與 `.2025-04-16` 是兩個檔案，以 `family` 串起來；`supersededBy`、`isCurrent` 由引擎算。
**理由：** 覆蓋舊檔就沒有異動對照，也沒有「AI 不能引用舊版」可言。Git 歷史雖保存了舊內容，但舊內容不再有穩定網址與 id。
**代價：** 檔案數增加；用 `family` 與命名規則控制。

## 9. 態勢狀態由人工發布

**決定：** `stable` `rising` `peak` `declining` 四級由疫情中心在後台填寫，附發布依據與資料日；模型不得產生，答案頁的態勢卡只讀 `v1/situation.json`，不生成數字。
**理由：** 這是專業判斷與機關對外宣告，責任歸屬必須明確。

## 哪些是示意資料、哪些是真實結構

**真實結構（可直接沿用到正式環境）：** 內容模型與 JSON Schema、治理規則與測試、API 外殼與路徑、URL 結構、三層露出元件、答案引擎流程、評估集格式、GitHub Actions 流程、`cdc:` 詞彙。

**來自官方來源的資料：** `data/snapshots/` 內的旅遊疫情、國家等級與 CKAN 資料目錄（每檔有 provenance 標示是即時抓取或快照）。

**示意資料（不可當真）：** 疫情態勢的狀態與數字（標「示意」）、致醫界通函第 616 號卡片（語料庫無通函時的版面示範）、「○○醫院 感染管制室」登入畫面、白名單核准日期與核准人、評估集題目與通過率、審閱日與承辦職稱、`pdfUrl` 中的占位網址。部分文字內容（如 MMR 建議、登革熱頁）依公開資訊撰寫，用來示範版本與連動，**正式上線前須由權責單位逐字審閱**。

**尚未實作：** 登入與真實的電子郵件通知、Webhook、伺服器端對話紀錄、API 金鑰與限流、LLM-as-judge 評估與人工抽樣工具。

# 人才招募個資處理原則

> 給誰看：人事室、資訊室、法務與個資窗口、資料治理委員會、需要說明「報名資料去哪了」的同事。
> 依據：《個人資料保護法》（下稱個資法）及機關個資保護與檔案管理規定；本站規則見 [governance-model.md](governance-model.md) 規則 19、20，操作見 [guide-staff.md](guide-staff.md) 第 16 節。
> 性質：**原型的設計原則與假設，不是法律意見。** 標「待確認」的項目（保存期限、告知事項正式文字、特定目的代號）須由人事室、法務與機關個資窗口在正式上線前定案。

## 一句話

**報名資料不在本站。** 本站只公布職缺、時程，以及甄選結果的「報名編號＋遮罩姓名」；報名資料由站外或後端的正式報名系統處理。原型裡的「線上報名」是模擬，只存在使用者自己的瀏覽器。

## 1. 報名資料不進 repo、不進 Git

- `content/` 與整個 repo（含 Git 歷史、CI 產物、GitHub Pages）**不得出現任何報名者的個人資料**：姓名全名、身分證字號、出生日期、電話、電子郵件、地址、學經歷、附件檔案。
- 本站是純靜態網站，沒有資料庫、沒有後端，**沒有任何能收件的地方**；因此報名資料不可能經由本站送到機關。
- 進入 repo 的與報名者有關的資料，只有人事室在結果公布時填的 `result` 與 `waitlistUpdates`，而且只含報名編號與遮罩姓名（見第 4 節）；建置閘門會擋下未遮罩者。
- 工作範例、測試資料與截圖一律使用虛構資料，不放真人姓名（與全站原則一致）。

## 2. 模擬報名：只存瀏覽器 localStorage，並明示

`/careers/{slug}/apply/` 是**原型示範**，目的是讓同事與委員看到完整的報名流程與介面，不是真的報名：

- 頁面上方有明顯橫幅：「原型示範：資料只存在你的瀏覽器，不會送出」；送出後的收執頁再次強調非正式報名。
- 三步驟表單（基本資料與聯絡方式、學經歷與應備文件、聲明與個資告知事項同意）的草稿（`cdc.apply.draft.{slug}`）與送出後的收執紀錄（`cdc.apply.receipts`），**只寫入使用者自己瀏覽器的 `localStorage`**；表單有「清除草稿」鍵；沒有任何網路請求把表單內容送出，本站與機關都看不到。
- 應備文件的「上傳」只記錄檔名，**不讀取、不上傳檔案內容**。
- 收執（報名編號 `CDC-{yyyymmdd}-{6 碼}`）可列印、可下載 JSON 與甄試日 `.ics`，由使用者自行保存；清除瀏覽器網站資料即永久消失，本站無法找回。
- 請同事示範時使用**虛構資料**，不要填入真人資料。
- 只有「開放中、且沒有外部報名網址（`applyUrl`）」的職缺才有模擬報名頁；已截止顯示「已截止」頁。**正式站不使用模擬報名**（見第 3 節）。

## 3. 正式站：報名系統在站外或後端

正式上線時，職缺頁的「線上報名」按鈕指向**外部報名系統**（`applyUrl`），例如人事行政總處的求才系統，或機關自建並經資安與個資審查的後端系統；email、郵寄、親送則在 `contact` 與應備文件寫清楚收件方式。

報名系統（不在本站範圍）至少應滿足：

| 項目 | 要求（待確認：由機關資安與個資窗口定案） |
| --- | --- |
| 身分驗證與存取控管 | 只有承辦人員依職務分工可讀取報名資料；有存取紀錄 |
| 傳輸與儲存 | 加密傳輸；靜態儲存的保護；備份一併納入保存與刪除管理 |
| 告知與同意 | 蒐集前提供第 8 節的告知事項；使用者確認後才送出 |
| 保存期限與刪除 | 依第 7 節；期限到後自動或定期刪除，並留紀錄 |
| 報名編號 | 系統產生，**不可由身分證字號、生日等推得**；本站公布結果時只用此編號 |
| 外洩事故處理 | 依機關個資事故通報流程 |

本站與報名系統的**唯一介面**：職缺頁的 `applyUrl`（外連），以及人事室在結果公布時從報名系統取得**報名編號**，連同遮罩姓名填入 `result`。本站不拉取、不快取報名資料。`applyUrl` 失效時會產生 `job-apply-url-dead` 待辦，由人事室向系統管理者確認。

## 4. 本站公布什麼：報名編號與遮罩姓名

結果與遞補公告只公布：

- **報名編號**（`candidateNo`）：3–24 個英數字與連字號（例：`1150924-012`）；不得像身分證字號或居留證號（`A123456789` 這類樣式在任何位置出現都擋下）；
- **遮罩姓名**（`nameMasked`）：含遮罩字（○、◯、〇、＊），且不得出現 3 個以上連續中文字的完整姓名樣式（例：「陳○明」可，「陳小明」不可）；
- 序號、備取名次與備取有效期。

**不公布**：電話、信箱、地址、出生日期、身分證字號、學歷與學校、成績、服務單位、照片。

這是**建置閘門**：違反者 `npm run build` 失敗、不能發布，不依賴承辦人記得去遮（[governance-model.md](governance-model.md) 規則 20）。遮罩規則的細節（複姓、少數民族姓名、外文姓名）為原型的預設，**待確認**。

**AI 不唸名單。** `result` 與 `waitlistUpdates` 不進 AI 白名單；問「誰錄取」時，答案引擎只提供結果頁連結並說明只公布報名編號與遮罩姓名。此外，使用者在提問框輸入的身分證字號、電話、電子郵件，依全站輸入防護先遮蔽再處理（[governance-model.md](governance-model.md) 第 5 節）。

## 5. 結果頁保存期限與下架

下列為**原型實際行為**與**建議值（待確認）**：

| 項目 | 規則 | 狀態 |
| --- | --- | --- |
| 結果公布後的前 90 天 | 顯示在 `/careers/` 的「錄取結果」頁籤；RSS 與 `/v1/jobs.json` 有一筆結果項 | 原型實作（自動） |
| 滿 90 天 | 自動移到「歷史」頁籤，頁面與結果仍保留供查閱 | 原型實作（自動） |
| 歷史頁保存多久、何時下架 | 建議：結果公布後保留 1 年，之後由人事室把該職缺 `status` 改為 `archived`（退出清單與索引、`noindex`），或移除 `result` 區塊只留公告 | **待確認**（依機關檔案管理與個資保存規定） |
| 遞補公告 | 與結果同一頁，同樣的保存與下架時程 | 同上 |
| 已取消、已補實的職缺 | 保留公告與狀態，無名單問題 | 原型實作 |

下架後：頁面不再出現在清單、搜尋與 AI 索引；舊網址依一般規則處理（`archived` 可保留頁面或 301 到 `/careers/`，由人事室決定，不得無聲 404）。

**Git 歷史的處理：** 因為進 repo 的只有遮罩後的編號與姓名，即使要求下架或刪除，通常不需要清除 Git 歷史。**若有任何未遮罩資料誤入 repo（例如草稿、PR 描述、截圖）**，視為個資事故：立即移除並關閉相關 PR；通知人事室與資訊室；必要時清除 Git 歷史與已建置的快取；依機關流程通知與記錄。建置閘門只擋「上架內容」，不保證擋得住所有誤貼，因此請不要在 Issue、PR、聊天工具貼出任何報名資料。

## 6. 備取名單有效期過後自動不顯示

- 每位備取可填 `validUntil`（備取有效期，依簡章，通常為公布後 3 至 6 個月）。
- **有效期過後，該筆備取在結果頁自動不顯示**，不需要人工刪除；有效期前 14 天，系統開 `job-waitlist-expiring` 待辦（低優先）提醒人事室確認是否還需遞補。
- 備取名單過期後仍留存在檔案與 Git 歷史（僅遮罩資料）；是否另行清理，依第 5 節的下架決定。

## 7. 申請查詢與刪除

兩個層次要分清楚：

1. **站外報名系統裡的完整報名資料**：當事人依個資法第 3 條可請求查詢或閱覽、製給複製本、補充或更正、停止蒐集處理利用、刪除。**受理窗口是人事室（及機關個資窗口），處理在報名系統端**，並依機關規定的時限回覆。本站職缺頁的 `contact` 與頁尾應提供這個窗口。保存期限屆滿的資料依規定刪除或去識別化（期限**待確認**，依機關檔案管理與人事資料保存規定）。
2. **本站公布的結果頁**：當事人認為遮罩不足或不願繼續公布時，向人事室提出；人事室查證後可更正遮罩、或移除該筆、或依第 5 節提前下架，並更新 `reviewedAt` 與於 `result.note` 記錄更正。處理時限比照一般個資請求。
3. **模擬報名資料**：在使用者自己的瀏覽器，本站與機關**沒有這些資料**，無從查詢或刪除；使用者自行清除瀏覽器網站資料即可。這點在模擬報名頁已明示。

## 8. 與個資法的對應

> 以下為原型說明，提供人事室與法務討論的起點；正式文字須由機關法務與個資窗口確認，並以現行條文為準。

| 個資法重點 | 本站的對應 |
| --- | --- |
| 蒐集與處理須有特定目的，並符合法定要件（公務機關：執行法定職務必要範圍內等） | 蒐集目的限於甄選與任用相關作業；站外報名系統只蒐集簡章所需欄位，**不多蒐**（原則：最小必要）。本站本身不蒐集 |
| 蒐集時應告知（個資法第 8 條：機關名稱、蒐集目的、個資類別、利用期間地區對象與方式、當事人權利與行使方式、不提供的影響） | 報名系統送出前顯示告知事項（範本如下）；模擬報名頁也放同一份範本，並加註「模擬，不蒐集」 |
| 利用不得逾越特定目的 | 報名資料不用於行銷或其他目的；本站結果頁只公布編號與遮罩姓名 |
| 當事人權利（個資法第 3 條、第 10、11 條） | 第 7 節的窗口與程序 |
| 安全維護與資料保存 | 報名系統端的存取控管、加密、紀錄、期滿刪除（第 3 節）；本站端以建置閘門避免誤公布（第 4 節） |

### 告知事項範本（供人事室與法務修訂；`{ }` 為待填）

> **個人資料蒐集告知事項**
> 衛生福利部疾病管制署（下稱本署）為辦理「{職缺名稱}」之甄選作業，依個人資料保護法第 8 條規定告知下列事項：
> 一、**蒐集機關：** 衛生福利部疾病管制署人事室。
> 二、**蒐集目的：** 人事管理（包括甄選、任用及其他與人事措施有關之事項）；{依機關核定之特定目的代號補充}。
> 三、**蒐集之個人資料類別：** 姓名、聯絡方式（電話、電子郵件、通訊地址）、出生年月日、國民身分證統一編號、學歷、經歷、考試與證照資料，及簡章要求之其他應備文件所載資料。
> 四、**個人資料利用之期間、地區、對象及方式：** 期間為本次甄選作業期間及法令規定之保存期間；地區為中華民國境內，如涉國際傳輸另行告知；對象為本署辦理甄選、任用之相關人員與依法有權查核之機關；方式為甄選、通知、任用及相關人事作業所必要之處理與利用。甄選結果僅公布報名編號及遮罩後之姓名。
> 五、**當事人得行使之權利：** 得向本署人事室請求查詢或閱覽、製給複製本、補充或更正、停止蒐集、處理或利用，以及刪除，聯絡方式：{人事室窗口}。
> 六、**不提供個人資料之影響：** 簡章所列必要資料未提供或不完整者，本署將無法受理報名或進行審查。
> 七、**資料保存與刪除：** 保存期限屆滿後依規定銷毀或去識別化：{依機關規定}。

模擬報名頁使用同一份範本，並在最前面加一行：「**本頁為原型示範，不會蒐集或送出你的任何資料。**」

## 9. 同事檢查清單

| 情境 | 檢查 |
| --- | --- |
| 建職缺 | 正式站：已填 `applyUrl`（外部系統）；沒有選用模擬報名；`contact` 有人事室窗口 |
| 上架結果 | 報名編號來自報名系統；姓名已遮罩；沒有任何電話、信箱、學校；建置通過；正取數 ≤ 名額 |
| 遞補 | 同上；不改動原 `admitted` |
| 備取到期 | 處理 `job-waitlist-expiring`；過期後確認結果頁不再顯示 |
| 收到查詢或刪除請求 | 依第 7 節，轉人事室與個資窗口；站內結果頁需調整時走 PR |
| 懷疑有未遮罩資料進入 repo、PR 或截圖 | 立即停止傳播、移除、通知人事室與資訊室，依第 5 節處理 |
| 示範模擬報名 | 只用虛構資料；講明「不送出任何資料」 |

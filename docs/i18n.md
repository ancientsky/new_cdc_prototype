# 多語工程筆記（第四十輪：issue #72 #73 #74 #76）

這份是給工程師的筆記：外語頁怎麼避免「漏中文」「漏 i18n key」、規則寫在哪、怎麼調。給同事的操作說明在 `docs/guide-staff.md` 第 40 節。

## 1. 原則

1. **檢查掃輸出，不掃模板**。漏字是「資料沒譯文 × 模板沒處理 fallback」組合出來的，看模板看不出來；所以建置最後掃 `dist/` 的可見文字（`scripts/lib/i18n-quality.mjs`），掃到就報。
2. **一種 fallback 只寫一次**。詞彙、標題、疫情數字各有一個 helper，模板一律呼叫 helper，不要在模板裡自己 `item.i18n?.[lang]?.title ?? item.title`：每個模板各寫一份，總有一份忘了處理。
3. **資料存欄位、文字由模板組**。疫情數字存 `metricNumeric` 加 `metricUnit`，外語由 i18n 範本組字（「23 local cases」），不要每個語言各存一串翻好的字：數字一改就會有語言忘了跟著改。
4. **機器翻譯一律標記、不進答案索引**。內容或詞彙用 `machineTranslated` 標記，頁面顯示「機器翻譯」；答案引擎只收 reviewed 譯文（index-builder 原本的規則，這輪沒改）。

## 2. 詞彙（#72）

- `src/client/glossary-term.js`：`glossaryTerm(g, lang)` 依序取該語言、en、zh-TW，**拒收任何 `term.` 開頭的值**（舊資料把 i18n key 當譯文存進去，印尼文首頁因此出現 `term.dengue`）。印尼文欄位名是 `id_`（避開 `id`），一律用 `glossaryField(lang)` 取，不要手寫。
- `glossaryTermInfo` 另外回傳 `machine`：主檔 `glossaryTerm.machineTranslated: ['tl','id']` 列出哪些語言是機器翻譯初稿。前台詞彙頁與後台詞彙管理都會顯示標記。
- 建置檢查：任何頁面可見文字（`<code>`、`<pre>` 除外，開發者頁的範例程式本來就會寫 `term.mpox`）出現 `term.xxx` 就失敗，不分 warn／error 模式。
- 待辦：21 個主檔疾病沒有詞彙條目，外語退回 `nameEn`。補詞彙會動到引擎的詞庫比對，這輪先不動。

## 3. 外語頁的中文比例（#73）

### 3.1 檢查

`checkI18nQuality(distDir)` 掃所有外語頁（zh-TW、ja 不掃；`assets` `files` `pagefind` `preview` `v1` `admin` `feeds` 不掃），計算「可見文字中漢字比例」：

- 不算進去的文字：`lang="zh…"`、`lang="ja…"` 元素裡的字（刻意標成中文的原文、語言選單的「日本語」）、`script` `style` `template` `noscript` `datalist`、白名單詞（預設：衛生福利部疾病管制署、疾病管制署、疾管署、繁體中文、中文）。
- 環境變數：

| 變數 | 預設 | 說明 |
| --- | --- | --- |
| `I18N_CJK_MAX` | `0.15` | 單頁漢字比例門檻 |
| `I18N_CJK_ALLOW` | （空） | 以逗號分隔，**加到**預設白名單 |
| `I18N_CJK_CHECK` | `warn` | `off` 不檢查；`warn` 只列出；`error` 超過門檻就讓建置失敗 |

- 結果寫到 `v1/governance/i18n-report.json`，建置摘要列出比例最高的 10 頁和例句。

### 3.3 helper

- `src/templates/public/_partials.mjs` 的 `localText(ctx, item, field)` 是外語頁取標題的唯一入口，順序是：該語言譯文；疾病用詞彙或 `nameEn`；英文；最後才是中文。退回中文時回傳 `zhOnly: true`。
- `titleLink(ctx, item)` 用 `localText` 產生列表標題連結：退回中文時加 `lang="zh-TW"`、`hreflang`，並加上「Chinese only」小標（`.c-zhonly`，文字是 `i18n.zhOnly`）。列表（最新消息、FAQ、徵才、採購、任務頁、首頁）都改用它。
- 疫情數字在 `src/client/situation-text.js`：`sitMetricValue` 依序用 `i18n[lang].metricValue`、`sit.unit.<metricUnit>` 範本（加上 `metricImported` 時的「(21 imported)」）、不含漢字的原值、純數字。`sitBasisInfo` 的判讀依據有該語言譯文（且不含漢字）就用，否則用通用句 `status.basis.generic`。建置 API（`emit-api.mjs`）預先算好各語言的值放進 `i18n`，前端答案卡直接讀。
- 首頁「原型」預覽列改用 `home.preview.*` 字串；有 `{x}` 的那句放在 `data-forced`，前端只替換變數。

## 4. 語言選單與「這頁沒有你的語言」（#74）

- 語言選單對**這頁沒有的語言**仍然列出，但連到該語言首頁，帶上 `?from=<原頁路徑>&alts=<有的語言>`，並顯示「(this page: English, 繁體中文 only)」之類的說明（`lang.pageOnly`）。不直接連到 404，也不默默跳回中文。
- 目標首頁的提示 `aside[data-from-hint]` **在建置時就產生好、預設隱藏**，前端只負責驗證 `from`（只允許站內路徑 `/^\/(?!\/)[\w\-./%]*$/`，擋 `//evil` 之類的開放轉址）、填連結、取消隱藏。文字已經是目標語言的建置期字串，前端不用帶各語言字串（公開頁 JS 預算 120 KB）。
- 疫苗頁（`/en/` `/vi/` `/id/`）多一張「多語兒童預防接種時程表」外連卡（`MULTILINGUAL_SCHEDULE_PDF`），標「連結待確認」：網址是同事提供的舊站頁，尚未驗證。
- 四種疾病（登革熱、腸病毒、結核病、流感）補了 id／vi／th／tl 的機器翻譯初稿，`languages[lang].status: "machine"`、`machineTranslated: true`。
  - **tier1 型別（疾病、疫苗、澄清、疫情）只輸出 reviewed 的語言**，所以這些譯文現在不會出現在前台，也不進答案索引；這是刻意的：醫療內容的機器翻譯不審核就上線風險太高。
  - **審核通過後怎麼開**：把 `languages.<lang>` 改成 `{ "status": "reviewed", "reviewedAt": "YYYY-MM-DD", "reviewer": "<單位或代號>" }`，刪掉該語言 `i18n.<lang>.machineTranslated`／`machineTranslatedAt`，重新建置即可。
- 評估集 `requires` 新增 `i18n:<內容 id>:<lang>`：該譯文 reviewed 才算存在。ML011（印尼文「Apa gejala demam berdarah?」）用它，審核前 skipped，審核後自動變成必考題，不用記得回來改題庫。

## 5. 來臺旅客／移居專區（#76）

- `content/topics/visiting-taiwan.json`：**用 topic 而不是 page**，因為 index-builder 不收 `page` 型別，用 page 的話答案引擎永遠找不到它。`sourceLang: "en"`：來源語言本身就會進索引，不用等英文譯文審核；zh-TW、vi、id 是機器翻譯初稿（未審核、不進索引）。
- 全部內容 `verification: pending`、來源 `verified: false`，權責單位是檢疫組（`unit.quarantine`），頁首有待確認橫幅。
- 句子不用分號：答案引擎以句為單位引用，分號會把一句切成兩半，引用時缺上下文。
- markdown 連結 `md()` 只加 basePath、不加語言前綴，所以專區內連結要寫完整的 `/en/travel/`。
- 首頁（en／vi／id 等外語）的旅遊卡分成「出國」與「來臺」兩半（`travelSplitCard`）；來臺那半在該語言沒有專區譯文時連到英文版並加 `hreflang`。
- 評估題 ML008–ML010。給引擎的已知問題：ML008（「What vaccines do I need before traveling to Taiwan?」）能引用專區，但第一句仍是國人出國的 MMR 建議，引擎應辨識「to Taiwan」的入境方向。

## 7. 答案頁介面字串七語齊備、單位名稱與態勢卡（第四十八輪，#100）

**症狀：** `/th/ask/` 的「回答」「僅引用官方內容…」「AI 整理」「接下來可以」「模型：抽取式…」是英文；`/en/ask/` 的來源卡寫「檢疫組」；`/tl/ask/` 的疫情卡是「Bagong lokal na kaso ngayong linggo，集中於南部縣市」（一句兩種語言）。

**做了什麼、為什麼比較好：**

1. **字串表搬家。** 答案頁的介面字串（約 150 個）原本是 `src/client/answer/render.js` 裡的 `S` 表，七種語言全部打包進每個語言使用者下載的 JS，而且 ja／tl／id／th 只翻了十幾個 key。現在放在 `src/client/i18n.ask.js`（key 一律 `ask.ui.*`），zh-TW、en、ja、tl、vi、id、th 每個 key 都齊。`scripts/lib/i18n-split.mjs` 在建置時把它另外拆成 `dist/assets/js/i18n.ask.<lang>.js`，只有答案頁（`/ask/`、`/data/`、`/factcheck/`）載入**當頁語言**那一份；其他公開頁的語言檔完全不含這些字串。好處：補齊四個語言沒有讓 JS 變大（最差的 `th/ask/` 提問後合計 239.4 → 239.0 KB，預算 240 KB），一般公開頁沒有多付。
2. **怎麼加／改一句：** 編輯 `i18n.ask.js` 該 key 的七個欄位（順序 zh-TW, en, ja, tl, vi, id, th），佔位符（`{n}`、`{q}`…）每種語言要一樣。`tests/round48-ask-i18n.test.mjs` 會擋：缺 key、佔位符不同、非日文語言出現中文。陣列型的字串（`reportKinds`、`channels`）用「|」分隔。新增 key 後在 `render.js` 用 `L('key')` 即可，不要再在 render.js 寫字串表。
3. **機器初稿，待審。** ja／tl／vi／id／th 的譯文是機器初稿（檔頭註明），上線前請母語審稿人逐條看，尤其是法規與通報用語（`notifyWithin`、`masterBasis` 等）與免責聲明 `disclosure`。
4. **單位名稱依頁面語言。** 索引分片裡的 `ownerName` 是中文，所以英文頁的來源卡顯示「檢疫組」。現在 `render.js` 的 `ownerLabel()` 用單位主檔（`content/master/units.json` 的 `nameEn`）查：非中文頁顯示英文名，主檔查不到才退回中文。主檔要新增單位時記得填 `nameEn`。
5. **疫情態勢卡不混語言。** 疫情中心填的 `metricLabel`／`deltaText`／`basis` 是整句，外語版常只翻一部分。規則：當頁語言三個欄位都齊才用當頁語言，否則**整張卡**改用英文版（英文缺的欄位不顯示，判定依據用通用說明），絕不出現「半句 tl、半句中文」。想讓 tl 卡顯示 tl，請疫情中心把 `i18n.tl` 的三個欄位補齊。
6. **「（另開視窗）」。** 外部連結的螢幕閱讀器提示原本寫死中文，改成 `ask.ui.newWindow`（七語）。其他模板本來就走 i18n key，dist 內非中文頁已沒有這個中文字面量（測試會掃）。
7. **倒數字串（#97 附帶）：** `notice.daysleft`／`notice.today`／`notice.closed.on`／`job.opensin`／`campaigns.daysleft` 補齊 ja／tl／vi／id／th，原本外語頁顯示英文「N days left」。

**中文比例檢查升級：** `scripts/lib/i18n-quality.mjs` 新增 `STRICT_CJK_PAGES`：`/<lang>/` 首頁與 `/<lang>/ask/` 超過門檻（15%）＝**建置失敗**；其餘頁面維持警告（目前全站仍有約 48 頁超標，多半是尚未翻譯的內容頁，全部改 error 會卡住每次內容更新）。`/ask/?q=…` 的答案由瀏覽器產生，不在靜態 HTML 裡，改由字串齊備測試保證。要把更多頁面納入：在 `STRICT_CJK_PAGES` 加一條，先確認該頁已低於門檻。

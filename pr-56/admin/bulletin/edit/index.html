示範原型：此後台不連接任何正式系統；登入與所有操作只存在你的瀏覽器（localStorage），正式環境以機關 SSO 登入、一律走 Git Pull Request。

疫情報導文章上架

一篇文章一次上架：選卷期（或建新的一期）、把稿件整篇貼進來讓系統切出摘要、前言、方法、結果、討論、參考文獻與圖表說明，核對作者、頁碼與圖表後匯出。右側一邊打一邊長出上線後的文章頁與本期目錄，點預覽任一區塊就跳到左側欄位。卷期頁的目錄由系統依卷期自動組，不必再手改卷期的篇目清單。

正式環境：填表 → 右側檢核全過 → 「產生上架包」（文章 JSON；新卷期多一個卷期 JSON；單篇 PDF 放 content/assets/{文章 id}/）→ 開 Pull Request → CI 以同一份規則驗證 → 合併即上線：文章頁、卷期目錄、搜尋索引、API、RSS 同步更新。

為什麼不用改卷期的篇目清單了以前每加一篇都要回去改卷期 JSON 的 articles[]、補頁碼、調順序，一期四篇就改同一個檔四次。現在每篇文章自己有 issueId 與 articleNo，卷期頁的「本期目錄」是建置時算出來的；舊的只有書目清單的期數照常顯示，兩種並存。

文章表單

選既有文章＝帶入全部欄位修改（id 鎖定）；「新增文章」＝空白表單。前台文章頁頁尾的「同事修改這頁」會直接開到這裡。
A 所屬卷期與篇次
自動帶本期最大篇次＋1；同期不可重複，決定目錄順序與網址。
填未來日期＝到那天才上線。
與同期其他篇重疊會擋下；排版定稿前可留空。
B 篇名與作者
刊載格式會印出單位；通訊作者在文章頁標＊。
負責複核與事件觸發審閱的署內單位。
      讓文章出現在疾病頁的「相關出版品」，也讓智慧查詢對得到。
      留空＝自動取摘要第一句。
      C 稿件：整篇貼進來，系統切段
      系統認得「摘要／前言／方法／結果／討論／結論／誌謝／參考文獻」這些標題（含「一、」「1.」等編號），「圖 1 …」「表 1 …」單行會抽成圖表說明。只填還沒填的欄位，不會蓋掉你已經改過的內容。

      D 摘要與重點
      文章頁頂端的摘要框；智慧查詢優先引用這一塊。

      重點三句話（仿 MMWR summary box，每句一兩行）

      這個主題以前就知道什麼。
      這篇多告訴讀者什麼。
      衛生單位、醫療院所或民眾該怎麼做。
      E 正文段落

      每段一個標題（前言、材料與方法、結果、討論、結論…），內文用 Markdown（### 可做小標、表格直接貼 Markdown 表格）。順序就是文章頁的順序。

      F 圖表

      每個圖或表要有編號與說明；表格把內容貼成 Markdown 表格（文章頁直接是 HTML 表格，可搜尋、可朗讀）；圖請填圖檔名（與 PDF 一起放 content/assets/{文章 id}/）並寫替代文字。系統會把圖表放在正文第一次提到它的那一段後面。

      G 參考文獻、誌謝、PDF
      只在你的瀏覽器記憶體；按「產生上架包」才會連同 JSON 打包。沒有單篇 PDF 時文章頁提供本期 PDF 與列印版。

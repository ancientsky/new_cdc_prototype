## 這個原型示範什麼

1. **治理是欄位，不是另一個系統。** 每筆內容必填權責單位、最後審閱日、審閱週期、對象、狀態、授權。缺一個，建置失敗，上不了線。
2. **人只填一次，機器算其餘。** 下次審閱日、逾期、失效版本、衍生內容待辦、AI 白名單資格、翻譯是否過期、KPI、季報，全部由欄位在建置時推導。
3. **AI 只轉述、不創作。** 預設答案引擎是「抽取式」：每句話就是白名單內容的一句原文並附來源編號；可選接 LLM（自備金鑰），輸出每句必須對得到檢索片段，對不上就刪。

## 規模與功能清單

- **規模**：內容 300 筆（疾病、疫苗、FAQ、新聞與公告、文件、澄清、資料集、影音、專區、申請服務、出版品、檢驗項目、研究計畫、職缺、標案）；七語靜態頁 2,605 頁（含 231 個目的地頁）；後台 18 頁；評估集 195 題（版本題 19）；治理測試 357 項。
- **內容型別（16 種）**：疾病、Q&A、新聞稿／通函／澄清、文件（版本鏈）、疫苗、資料集、Banner、一般頁，加上第二輪新增的**影音、專區、申請服務、出版品、檢驗項目、研究計畫**，以及第七輪獨立出的**人才招募（`job`）、採購公告（`tender`）**。
- **民眾端**：一句話提問、六任務、疫情態勢、疾病與疫苗、旅遊、謠言查證、影音庫、專區、申請專區、公告、署長信箱。
- **專業端**：版本異動對照、檢驗專區、通報專區（時限表自動產生）、研究計畫、出版品、訂閱。
- **後台**：上架預處理（十五種型別，含發布車道徽章、排程與緊急發布、模擬送出）、複核、審閱到期、資料目錄（含影音、專區、申請、出版品、檢驗、研究）、**公告管理、影音管理、外部連結健康**、連動待辦（含影音過時、無逐字稿、連結失效、檢驗不一致）、疫情發布、AI 開關、評估、儀表板。
- **出國與入境（第四輪）**：以目的地為主：231 個國家／地區各有目的地頁（針對性等級、持續時間、長期建議標籤、旅程三階段建議由疾病主檔規則生成、該國近 30 天疫情資訊）；`/travel/` 依序為查目的地、近 30 天變化、世界地圖（三級三色、點國家進頁）、全球背景提醒、針對性等級表；API 新增 `/v1/country-changes.json`、`/v1/country-background.json`。
- **新增的自動化**：公告截止自動標示並退出首頁；影片製作日早於正本現行版生效日自動標過時；逐字稿參與反向稽核；外部連結每日 `npm run fetch -- --check-links` 檢查，失效自動變待辦；通報時限表由主檔產生。

## 第五輪：舊網址不 404，結核病專區移轉示範

舊網站的內容不會因為改版而不見，舊網址也不該變成 404。第五輪用**結核病專區**走完一整套「舊頁 → 新頁」的流程，做法可以套到其他 98 種疾病與所有欄目：

- **移轉清單**：`content/migration/tuberculosis.json` 逐筆列出舊頁（標題、舊網址、類型）、處理方式（已移轉／已併入／已封存／待確認／已移除）、對應的新內容與段落。權責單位在後台 `/admin/migration/` 逐筆確認（`verified`）；舊網址 ID 取不到者以 `{id}` 佔位，確認時補上。
- **新擺法、新要求**：結核病疾病頁加上專區導覽（民眾／專業各一套），指引與手冊走文件版本鏈，另有 Q&A、專區、補助與潛伏結核感染治療服務；頁首治理列有「本頁取代舊網站 N 個頁面」，展開看每筆舊網址與移轉後新增的治理要求。
- **舊網址不 404**：建置自動輸出 `v1/redirects.json`、`v1/legacy-map.json`，以及三種伺服器轉址檔 `redirects/nginx.map`、`redirects/web.config.rewritemap.xml`、`redirects/_redirects`；404 頁自動帶往新頁，`/legacy/` 可貼舊網址查新頁。靜態主機的 404 頁只是示範與備援，**正式站必須由伺服器回 301**。
- **上線後監測**：`node scripts/analyze-404-log.mjs access.log --map dist/v1/legacy-map.json --migration content/migration` 把 404 log 分成「可直接 301」「待補對照」「真的不存在（建議 410）」三類，待補對照附可貼進清單的草稿。
- **規劃回補**：整理了 39 項「規劃文件沒寫到、原型做了」的作法，見 [docs/plan-supplement.md](docs/plan-supplement.md)（第 29–39 項為後四輪新增）；完整移轉與轉址手冊見 [docs/migration-playbook.md](docs/migration-playbook.md)；同事操作步驟見 [docs/guide-staff.md](docs/guide-staff.md) 第 15 節。

> 限制：開發環境連不到 `www.cdc.gov.tw`，結核病專區的舊頁清單依規劃文件的 URL 模式重建，每筆標 `verified: false`，等權責單位確認。

## 第六輪：移轉套用到全部疾病、國際合作區塊、內容來源語言

第五輪證明「一個專區走完整套」可行；第六輪回答「99 種疾病怎麼辦」，並補上舊站只有英文版的國際合作區塊：

- **移轉套用全部疾病（推導清單 → 只寫例外）**：舊站每個疾病頁的子頁結構相同，所以標準子頁樹寫成一份模板 `content/migration/_disease-template.json`，治理引擎對主檔**每一種疾病**推導一份移轉清單（原型主檔 72 種：16 種已有疾病頁，其餘標 `no-page`）；有疾病頁且新站有對應內容就算已移轉／已併入，沒有就是待移轉。人工清單**只寫模板沒有的例外**（疾病特有專區頁、專屬指引與公告），同 `key` 覆蓋推導結果。待辦每份清單只開一則，優先度依法定類別。結核病之外，登革熱、流感、麻疹、腸病毒也回補了防治計畫（`professional.programs`）、文件、Q&A 與例外清單。後台 `/admin/migration/` 看 72 份清單進度，`/v1/migration/{slug}.json` 可下載當人工清單的起點。
- **國際合作區塊**：舊英文站的 International Cooperation 移到新站（IHR 國家聯絡窗口、多邊與雙邊合作、國際訓練與申請、英文出版品與新聞），入口為 `/international/`，主選單不增項，放在研究與媒體入口與頁尾。
- **內容來源語言 `sourceLang`**：國際合作內容以**英文為來源語言**、中文為必備的審核譯文：頂層欄位是英文，中文放 `i18n['zh-TW']`；缺中文譯文建置失敗；頁首標示「本頁以英文為準，中文為譯文」。逾期、譯文過期、白名單等治理規則照常運作。
- **規劃回補與手冊**：[docs/plan-supplement.md](docs/plan-supplement.md) 新增第 29–31 項（推導清單、sourceLang、國際合作雙語）；[docs/governance-model.md](docs/governance-model.md) 新增規則 17、18；[docs/migration-playbook.md](docs/migration-playbook.md) 新增第 10 節「規模化：99 種疾病怎麼做」；[docs/guide-staff.md](docs/guide-staff.md) 第 15 節改為「推導清單 → 只寫例外」流程。

> 限制：推導清單的舊網址一律以 `{id}` 佔位（標 `pattern`），不進伺服器轉址檔；要讓 301 真的生效，需向資訊室取得舊站 ID 對照（見 playbook 第 10.5 節）。英文站 `/En` 同樣連不到，國際合作的舊頁清單依既有認識重建，全部 `verified: false`。

## 第七輪：人才招募與採購公告分家、招募生命週期、模擬報名

第二輪把人才招募與採購公告放在新聞稿底下，只有一個截止日。第七輪把兩者拆開，各有權責單位與自己的生命週期：

- **人才招募與採購公告分家**：人才招募成為獨立的 `job` 型別（`/careers/`，權責**人事室**，新單位 `unit.personnel`），採購公告成為 `tender` 型別（`/procurement/`，權責秘書室）。`news` 不再有招募與採購兩種；舊 `/news/{slug}/` 網址 301 到新路徑。頁尾「更多服務」也拆成「人才招募」「採購公告」兩個入口。
- **招募生命週期（日期推導，不靠人記）**：即將開放 → 報名中 → 已截止 → 審查與甄試中 → 結果公布 → 90 天後進歷史；人工只有「取消」「已補實」兩種覆蓋。職缺頁有**時間軸**標示目前階段，已截止頁寫明「結果預計 {日期} 公布」。三個待辦：結果逾期、備取將到期、外部報名網址失效。備取名單過有效期後自動不顯示。
- **模擬報名「不送出任何資料」**：`/careers/{slug}/apply/` 是三步驟的示範表單（即時驗證、草稿、收執可列印、可下載 JSON 與 `.ics`），**資料只存在你的瀏覽器 localStorage，不送出任何資料**，頁面明示為原型示範。正式站的報名系統在站外或後端（職缺填 `applyUrl`），本站只公布職缺、時程與結果。
- **個資遮罩閘門**：甄選結果與遞補公告只公布**報名編號與遮罩姓名**；`nameMasked` 必須含遮罩字（○）且不得有完整姓名樣式、`candidateNo` 不得像身分證字號、正取數不得超過名額，**違反即建置失敗**。AI 白名單排除名單，答案引擎問「誰錄取」只給結果頁連結。
- **採購公告狀態化**：招標中 → 已截止 → 已開標 → 已決標（或流標、取消），決標逾期自動開待辦；本站只做入口與狀態，**正式公告以政府電子採購網為準**。
- **文件**：[docs/careers-privacy.md](docs/careers-privacy.md)（招募個資處理原則）；[docs/guide-staff.md](docs/guide-staff.md) 新增第 16 節（人才招募 SOP，人事室）與第 17 節（採購公告 SOP，秘書室）；[docs/governance-model.md](docs/governance-model.md) 新增規則 19–21；[docs/plan-supplement.md](docs/plan-supplement.md) 新增第 32–34 項；[docs/migration-playbook.md](docs/migration-playbook.md) 新增 10.8「欄目型清單：人才招募、採購」。
- **輸出**：`/v1/jobs.json`、`/v1/tenders.json`（含階段）、RSS `feeds/careers.xml`、`feeds/procurement.xml`、JSON-LD `JobPosting`；後台 `/admin/jobs/`（人事室：職缺與階段、待辦、結果上架檢核）、`/admin/tenders/`（秘書室）。

> 限制：連不到 `www.cdc.gov.tw`，舊站「人才招募」「採購公告」欄目的移轉清單（`content/migration/careers.json`、`procurement.json`）依既有認識重建，全部 `verified: false`。示範資料中的職缺、錄取名單（報名編號與遮罩姓名）與決標廠商皆為虛構，不可當作真實公告引用。

## 第八輪：上架功能補完：所見即所得編輯、附件與圖片的放法

前幾輪的上架流程要同事「貼 Markdown、手寫附件網址」。第八輪補上兩個缺口：不會 Markdown 的人怎麼寫內文，以及附件與內文圖片放哪裡、建置時檢查什麼。**正本仍是 Markdown＋JSON**（可 diff、可機讀、可給 AI），所見即所得只是輸入方式。

- **三頁籤內文編輯**：`/admin/publish/` 內文欄有**所見即所得／Markdown／預覽**三個頁籤，同一份資料、即時轉換；工具列有標題、粗斜體、清單、連結、表格、圖片、引用；貼上 Word 或網頁內容時自動清成支援的子集。**存檔一律是 Markdown**。
- **附件與圖片面板**：拖放多檔；檔名自動正規化（中文檔名要自己改）、選 `kind`（附件／內文圖片／資料檔）、填 label 與 alt、授權與來源、PDF 是否有文字層、算 SHA-256；一鍵把圖片插進內文。
- **上架包**：「產生上架包」下載 **ZIP**（內含 `content/{型別}/{id}.json` 與 `content/assets/{id}/…` 原檔），畫面列出放哪裡與 PR 指引；解壓到 repo、開 PR、CI 檢查即可。
- **檔案放哪裡**：`content/assets/{內容 id}/` → 公開網址 `/files/{內容 id}/{檔名}`（七語共用，不帶語言前綴）；內容用 `assets[]` 宣告每個檔。檔名只能小寫英數、連字號、底線與點。
- **建置閘門**：檔案存在、`sha256`／`bytes` 相符、格式與大小在限制內（PDF ≤ 20 MB、圖片 ≤ 2 MB、資料檔 ≤ 50 MB）、SVG 無腳本、內文 `/files/` 引用都有宣告；**圖片沒有 alt 或授權直接建置失敗**；孤兒檔開待辦。hash 不符時訊息印出實際值，`npm run build -- --fix-assets` 可自動補寫 `bytes`／`sha256`／`mime`／寬高。
- **PDF 可及性**：PDF 沒有文字層又沒附 `.md`／`.docx` 替代版 ⇒ 待辦 `attachment-no-accessible-version`。
- **文件**：[docs/assets-policy.md](docs/assets-policy.md)（新）；[docs/guide-staff.md](docs/guide-staff.md) 第 2 節重寫為完整上架 SOP（三種編輯方式、附件與圖片、上架包、常見錯誤）；[docs/governance-model.md](docs/governance-model.md) 新增規則 22–24 與共同欄位 `assets`；[docs/plan-supplement.md](docs/plan-supplement.md) 新增第 35–36 項；ARCHITECTURE §16。

> 限制：原型的建置檢查不做**病毒掃描**與**個資偵測**，PDF 文字層只有簡易偵測（宣告 `machineReadable: true` 卻偵測不到時警告；標籤與閱讀順序無法判斷，`machineReadable` 是承辦人聲明，由複核者抽查）；這些列為正式站待辦，見 [docs/assets-policy.md](docs/assets-policy.md) 第 10 節。範例檔案皆為本輪由 `scripts/gen-sample-assets.mjs` 產生的示意檔。

## 第九輪：發布車道與自動合併、預覽網址、預定與緊急發布、舊站匯出批次轉換

目標：承辦人感受到的流程**跟舊後台一樣簡單**（登入 → 選型別 → 填標題 → 貼內文 → 拖附件 → 送出，一樣 6 步），治理在背後自動發生；並示範舊站匯出一鍵轉成內容草稿。原型沒有後端，所以後台的「送出」是**模擬**（產生上架包 → 開 PR 的時間軸展示），**但 PR 之後的一切在 GitHub Actions 上真的會跑**。

- **三條發布車道**（`content/governance/lanes.json`，由系統依型別判定）：**快車道**（新聞稿、通函、澄清、職缺、採購、Banner）CI 通過就自動合併，約 3 分鐘上線，公關室 24 小時內複核；**一般車道**（疾病、疫苗、文件、Q&A、專區…）CI 通過還要 1 位審核人核准（疾病與疫苗為公關室＋OASIS），SLA 2 個工作天；**緊急發布**（疫情態勢，以及標了 `urgent` 的新聞稿／通函／澄清）10 分鐘內上線。一個 PR 含多種內容時取最嚴格的車道。**CI 是第一位審核者**；多語不擋中文。
- **後台 `/admin/publish/`**：型別一選就顯示**車道徽章**與一句說明；新增「**排程發布**」（`publishAt`，臺北時間）與「**緊急發布**」（`urgent`，只對新聞稿／通函／澄清顯示）；預檢加「urgent 只能用於允許型別」「`publishAt` 必須晚於現在」；預處理結果最下面「**模擬送出**」展開時間軸：建立分支 → 開 PR → CI 檢查（schema、治理規則、評估集、檔案資產、連結）→ 車道判定 → 自動合併／等待審核（列審核人與 SLA）→ 部署 → 預覽網址，每步附「正式環境由系統代做」。模擬送出**不呼叫任何 API**。

Yulun 問（2026-10-13）：現行官網是 mega menu，新原型的主選單要不要也做？評估結論是**不要照搬那種滑鼠移過去展開整面的**；但 mega menu 沒有退流行，只是做法換成「點擊展開、每項最多 9 個連結、手機改手風琴」。Yulun 核准後這一輪實作了最小版本。完整評估與設計理由見 [docs/navigation.md](docs/navigation.md)，工程契約 ARCHITECTURE §50，無障礙對照 [docs/a11y.md](docs/a11y.md) 第 8 節。

> 註記：現行 cdc.gov.tw 的選單結構是從搜尋快取與衛福部頁面推斷，沒有直接連線確認，項目數與順序請以官網為準。

### 做了什麼

- **主選單仍是八項扁平**，只在「傳染病、疫苗、出國與入境」三項旁邊加一個 ▾ 鈕，點了展開一個小面板（兩欄，4–9 個連結，最後一個永遠是「前往○○專區 →」；傳染病面板的疾病最多 4 個，因為 4 + 欄二 4 個 + 前往專區 = 9 的上限；疫苗面板略過本語言沒有版本的項目，外語頁選單才不會夾雜中文）。疫情、闢謠、資料、新聞、常見問答五項不變。
- **手機**併入既有的「選單」面板，面板變成手風琴（在文件流中展開，不浮動）。
- **內容不另維護**：疫苗面板與 `/vaccines/` 的 `.vx-hub` 共用同一個函式；傳染病面板依序取「目前疫情」對應的已發布疾病頁（不足才補最新審閱的）；出國面板只連到 `travel.mjs` 真的輸出的錨點（沒有獨立的疫情列表路由，列表就是 `#tv-nw-h` 區塊，所以不另放連結）。
- **七語齊備**，後台不受影響。

### 為什麼這樣做

- **用 `<details>/<summary>`，不自己寫 button**：無 JS 也能開合，鍵盤與讀屏原生支援，與第二十四輪手機語言選單同一套；JS 只做 Esc、點外面關閉、一次只開一個（ui.js 原始碼增加 1,057 bytes，建置後 20.5 KB；公開頁 JS 最大 64.5 KB，預算 120 KB）。`focusout` 只在焦點確定移到面板外時才關，否則點面板內的純文字就會把面板收起來。
- **不 hover**：觸控與鍵盤沒有 hover、滑鼠誤觸會遮內容、WCAG 1.4.13 最常失分；CSS 裡不准有 `:hover` 開面板的規則，測試會掃。
- **內容由資料推導**：選單與入口頁不同步是最常見的壞法；錨點被改掉時建置就失敗，不會變成悄悄壞掉的連結。
- **每面板 ≤ 9 個**：再多就是把網站導覽頁塞進頁首。
- **一個 CSS 陷阱**：`.c-nav__in` 有 `overflow-x:auto`，面板若定位在它裡面會被裁掉；所以面板的 containing block 設在 `.c-nav`，各層 item／details／summary 都不設 `position:relative`。

### 怎麼驗證

`tests/round47-nav-panels.test.mjs`（9 個測試）：七語首頁各恰好 3 個 `details[data-nav-dd]`、summary 無 `aria-*`／`role`、面板 id 唯一、每面板 4–9 個連結且全部指向存在的輸出檔與錨點、疫苗面板每個連結都在 `.vx-hub` 內、傳染病面板依序含目前疫情的已發布疾病頁且 ≤ 4、`/pro/` 與 `/` 都含 `c-pro-only` 連結、面板內沒有標題、base.css 無 hover 規則與定位正確、ui.js 含 `data-nav-dd`／`Escape`／`focusout`、後台不含 `data-nav-dd`；Playwright 端到端（1280px 點開／換開／Esc 焦點回 summary／點外面關；390px 手風琴在文件流中；開面板後 axe 無 serious／critical；沒有 dist 或 chromium 時略過；另驗證面板沒被 overflow 裁切（`elementFromPoint`）與手機版面，axe 在 1280px 開傳染病面板後掃整個首頁）。`tests/round6-ui.test.mjs` 計算選單連結前會先去掉 details 區塊。

### 本輪學到的

- **相容字（NFC）**：文字層給的「劉」是 U+F9C7（CJK 相容表意文字），肉眼相同但碼位不同，比對失敗；原始文字一律先 NFC。
- **旋轉的側標字**：頁邊直排字（旋轉 90°）會被讀成一般文字黏進行；跳過 transform 顯示旋轉的字塊。
- **隱藏的疊印文字**：42(17) 把看不見的「疫情描述」疊在單位名同一座標；丟掉完全落在別的字塊範圍內的字塊。
- **頁尾文字層可能缺字**：「疫情報 導」少了一個字，頁碼就推不出來；比對要容許缺字。
- **`SIDEBAR_RE` 會誤殺 Markdown 表格列**：丟側標的規則太寬，把 `| … |` 的列也吃掉；收窄到中間不可有空白。
- **`FIG_RE` 會把句子當圖說**：「圖二為…」是句子；中文數字後必須接「、」或空白才算圖說。
- **舊版整期合刊 PDF**：一份檔多篇文章，第二個「摘要」之後要切掉並提醒改單篇；舊版文字層逐字有空白（「8 ,2 4 5」），數字需人工清。

> 限制：2013 以前的 PDF 數字裡有空白；列名垂直置中的表折行值可能掛錯列；第一資料列折行會併進表頭；無編號「表、」只留在正文；掃描檔、向量圖、整期合刊只帶第一篇的限制不變。「依版面推測的標題」是猜的，要核對。

## 第四十五輪：《疫情報導》上傳 PDF 就自動帶入欄位、全文與圖，審批後直接上架

同事問（2026-10-13）：**能不能上傳疫情報導的 PDF，後台自動 parsing 成需要的欄位及全文，審批後上架，不要再人工逐一欄位填寫？** 可以，原型做出來了：PDF 拖進後台 → 欄位、全文、圖自動帶入（1 秒）→ 核對、檢核 → 「送審」→ 科長「核准上線」→ 文章、卷期、PDF、圖一起進正式庫。不填欄位、不打包 ZIP、不碰 Git。完整說明 [docs/bulletin.md](docs/bulletin.md) §14，同仁 SOP 手冊 §45。

### 做了什麼

- **瀏覽器端讀 PDF**：pdf.js（legacy 版，vendor 進 `src/public/vendor/pdfjs/`，只有後台用、用到才載入）讀文字層與內嵌圖片；PDF 不離開同事的電腦。
- **切段規則只有一套**：`pdf-manuscript.js` 把 pdf.js 的字塊依座標排回「一行一行」的版面文字（和 `pdftotext -layout` 同形），交給第三十五輪的 `splitManuscript`，一個字都沒改就把真實文章 42(19) 的篇名、7 位作者、單位、DOI、日期、關鍵字、分類、摘要、7 段正文、圖說、11 筆文獻、英文摘要全部帶入。
- **圖自動配**：抽出的圖依「圖 N」圖說所在頁配對，太小、重複的刊頭圖略過，配不到的列縮圖讓同事「當作圖 N」；配到的圖自動命名、算 sha256、宣告進 `assets[]`。同一份 PDF 自動成為「單篇 PDF」附件。
- **送審件帶附件與配套內容**：寫入閘道（第三十輪）的 `/drafts`、`/submit` 可帶 `files[]`（PDF、圖）與 `companions[]`（新的一期），同分支、同次核准、同一個合併上線；閘道用建置同一支 `validateAssets` 查附件的 bytes／sha256／內容，「後台通過＝CI 通過」在有附件之後仍然成立。上限整包 24 MB、附件 16 MB、20 個檔。
- **實測**（Chromium）：真實 PDF 上傳 → 全欄位帶入 → 存草稿 → 送審 → 科長核准 → `main` 多了文章、卷期、`fig-1.png`（與抽出的圖逐位元相同）、PDF（與上傳檔逐位元相同），提交有 `Edited-by`／`Approved-by`。
- **測試**：`tests/round45-pdf-gateway.test.mjs`（7 項）。

### 教訓

- **pdf.js 會轉移 ArrayBuffer**：讀完後原本的 bytes 變成空的，第一次實測送出去的 PDF 附件是 0 位元組；交出去前先複製。
- **vendor 用 legacy 版、檔名用 `.js`**：一般版用了很新的 `Map.prototype.getOrInsertComputed`，舊一點的瀏覽器整個載不起來；`.mjs` 在 IIS 等伺服器預設沒有 MIME，瀏覽器拒絕當模組載入。
- **讀 Git 裡的二進位檔不能經過字串**：本機 Git 供應者把 `cat-file` 輸出一律 `String()`，圖讀回來多了 80%，「不重傳附件再存一版」被自己的 sha256 檢查擋下。
- **刊頭的加寬字距**：「疫 情 調 查」在文字層裡字與字之間有空白，分類比對要先去空白。

> 限制：掃描檔（無文字層）讀不到字；向量圖抽不出來，同事仍要自己存 PNG；最多讀 60 頁；配圖是依頁的啟發式，縮圖與預覽的核對不能省。GitHub Pages 展示站沒有寫入閘道，第 4 步退回「產生上架包」。

### 教訓

- **「放行」要寫成規則，不要寫成白名單**：一開始最省事的做法是把三個姓名加進 `pii-allowlist.json`。但那會讓白名單變成一份人名清單（本身就是個資的集合），而且首長換人時要有人記得去改。改成「簡介檔只放行自己的 `profile.name`」之後，規則對任何一任首長都成立，審核人也不必判斷「這個姓名為什麼可以」。比較好，因為規則可以測試、可以解釋，白名單只能相信。
- **放寬一處就要收緊一處**：放行姓名的同時加了 `profile-private` 檢查。各部會首長頁偶爾會抄進出生年月日、籍貫（Wikipedia 也有），新站一律不放——「與公務職位有關」是界線，寫進 schema、掃描器、後台預檢與同仁手冊四個地方，同一份清單（`PROFILE_PRIVATE`）。
- **網址用職位不用人名**：`/about/leadership/director-general/` 在首長異動時不變；用人名當網址，每次換人就多一個壞連結、少一段搜尋權重，還會留下前任的網址在搜尋引擎裡。
- **「不刊登姓名」的舊說法要一起改**：第一輪的署長職掌頁寫「不刊登個人姓名與照片」，當時是為了迴避個資問題；本輪把那句話改掉並連到首長簡介，否則兩頁會互相矛盾（第三十三輪的說法一致性檢查管的是數字，管不到這種）。
- **`/img/` 不加語言前綴**：首長頁的占位圖第一次建置在六個外語版的關於頁出現 404——照片網址要走 `imgSrc()`（`noLang`），和專區圖片同一條規則。

> 限制：(1) 三頁內容都**未逐字核對**（搜尋摘要、媒體報導），英文版經歷年份與中文版不同（英文官網分 2003–2006 住院醫師、2006–2008 感染科研究員），兩位副署長的學經歷與英文拼法待秘書室提供；(2) 沒有正式照片，顯示占位圖；(3) 首長簡介的法規依據（政府資訊公開法第 7 條機關組織資訊主動公開、個資法對公務機關執行法定職務之規定）是原型整理的理解，請法規會或個資窗口確認措辭；(4) 主任秘書頁 schema 已允許（`chief-secretary`）但本輪未建，秘書室要時從後台新增即可。

## 第四十三輪：國際疫情資訊從疫情中心資料庫自動上架

疫情中心同事問（2026-10-13）：他們有自己維護的資料庫，未來上架「國際重要疫情資訊」有沒有更聰明或自動化的方式？查下去發現，新站 `/travel/` 的「近 30 天國際重要疫情資訊」本來就是每天從現行官網 `TravelEpidemic/ExportJSON` 拉來的，而那個匯出檔的欄位（`sent`、`effective`、`headline`、`alert_disease`、`areaDesc`、`ISO3166`…）就是 CAP 格式——背後正是疫情中心的資料庫。所以答案不是另造一條路，而是**把今天隱含的格式寫成白紙黑字的契約，讓資料直接從中心資料庫進新站**。設計與契約在 [docs/intl-epidemic.md](docs/intl-epidemic.md)，工程契約 ARCHITECTURE §47，決策 [docs/architecture-decisions.md](docs/architecture-decisions.md) §32，同仁 SOP 在同仁手冊 §43。

### 四種做法，一句話比較

| 做法 | 一句話 | 結論 |
| --- | --- | --- |
| A. 後台表單（承辦人再填一次） | 兩個正本、抄錯漏登，等於叫中心多做一份工 | 只當**備援**（系統斷線時貼上） |
| B. 排程拉取（CI 向中心匯出端點拉） | 中心只給一個網址＋唯讀 token，今天的流程只是換掉 URL | **預設做法** |
| C. 推送（中心核定時 POST 到網站） | 分鐘級上線，但要開網路通路、管 token | **加值選項**，急件需要時再開 |
| D. 訂閱標準 feed（RSS／CAP XML） | RSS 會丟掉國碼與疾病對應；CAP XML 雙方都要寫 XML | 不另做；我們的 JSON 就是 CAP 欄位 |

**選定：一份契約＋ B 為主、C 為輔、A 為備援，三條路進同一個匯入器、同一套把關規則。** 網站端**不再加一道人審**——資料庫裡的那一筆已經是中心依既有流程核定的內容，網站該做的是機器把關與事後可見（待辦、匯入紀錄）。

### 做了什麼

- **交換格式 v1**（`schemas/intl-epidemic-feed.json`）：`{ version, producer, generatedAt, mode: full|delta, items[] }`，每則有穩定 `id`、`status`（published／updated／withdrawn，撤下只需 id）、發布／更新／下架時間、疾病、標題、內文、`areas[]`（國名、ISO 國碼、地區細節）。另接受等價的 **CSV**（一則一列、多國以 `;` 分隔）與**現行官網 ExportJSON 舊格式**，讓切換資料來源不必一步到位。
- **一個匯入器**（`scripts/lib/intl-epidemic.mjs`，CLI `npm run intl:import -- <檔案或 URL> [--dry]`）：讀入 → 驗證（schema＋白話錯誤＋個資掃描）→ 對主檔 → 比對上一版 → 寫檔。單則有錯只退回該則（網站保留它的上一版）；退回超過 20%、full 模式收到 0 則、或會讓清單少掉一半以上 ⇒ **整批保留不動**；與上次完全相同 ⇒ 不寫檔、不產生 commit。疾病或國家對不上主檔照常上架，但列待辦請中心補別名。
- **排程拉取接上**：`npm run fetch` 看 `INTL_FEED_URL`（＋`INTL_FEED_TOKEN`）有設就拉中心的 v1 feed，沒設維持官網匯出；兩者都經過匯入器。CI 從 secrets 帶入。今天的快照已用舊格式跑過一次匯入器重寫：既有欄位逐列不變，多了 `id`、`status`、`areas`、`body`、`diseaseId`、`provenance`。
- **推送端點與後台頁（規格，另一位同事同時實作）**：`POST /api/intl-epidemic`（Bearer token、≤ 2 MB、整批保留回 202），閘道 `POST /api/gateway/intl-epidemic/import`（登入＋CSRF，限疫情中心與跨單位管理角色，可先 dry 預覽），後台 `/admin/intl-epidemic/`（匯入狀態、退回與對不上清單、現行清單、歷史；貼上／上傳 JSON 或 CSV、單則表單 → 預覽 → 送出；沒有閘道就下載 JSON 交資訊室跑 `npm run intl:import`）。
- **前台**：每則有自己的頁 `/travel/alerts/{id}/`（內文、疾病頁與目的地頁連結、來源、七語骨架、JSON-LD、`.md` 機讀版）；`/travel/` 與目的地頁列表改連站內頁，原始網址改小字「原始來源」；新 RSS `feeds/travel-alerts.xml`（guid＝資料庫 id，更新不會變成新的一則），加入電子報訂閱主題。
- **待辦**：`intl-feed-held`（整批保留，高優先、1 天）、`intl-feed-unmapped`（對不上主檔，14 天），權責都是疫情中心。
- **測試**：`tests/intl-epidemic.test.mjs`（20 項）、`tests/travel-alert-ui.test.mjs`（11 項）。

### 教訓（全部 12 條在 docs/intl-epidemic.md 第 8 節）

- **新欄位先查誰在讀舊欄位**：原本想把 full／delta 記在快照 `meta.mode`，但 `/travel/` 已經用 `meta.mode` 判斷「即時／快照」；改記在 `meta.importMode`。比較好，因為前台的資料狀態標籤不會悄悄變錯。
- **真實資料比規格亂**：官網匯出有些列沒有疾病或國家欄位（例「美國-環孢子蟲病」），要從標題「國家-疾病」補；內文混有康熙部首字（⽐、⾮、⻑），主檔比對前要先 NFKC。不處理就會大量退回或對不上。
- **full 模式下被退回的那則不等於撤下**：原本「這批沒有＝撤下」，會讓一則因格式錯而從網站消失；改成保留上一版。比較好，因為資料有錯的代價不該是民眾看不到既有資訊。
- **內容指紋一改就是資料遷移**：改 `itemFingerprint`，下次匯入會全部變成「更新」，RSS 也跟著跳；要當資料遷移寫說明。
- **新增 RSS 頻道不只改一個檔**：訂閱主題清單、七語主題名、round28 測試的頻道數都要同步。

> 限制：(1) `data/samples/` 的範例是**示意資料、未驗證**；(2) 疫情中心資料庫的**真實 schema 未知**，v1 是我們提出的約定格式，要請中心回答 docs/intl-epidemic.md 第 7 節的問題後校準；(3) 開發環境**連不到 cdc.gov.tw**，快照的重寫以 repo 裡既有快照為準，拉取與推送都沒有對真實端點驗證過；(4) 現有快照有 7 個疾病名稱對不上主檔（沙門氏菌感染症、細菌性腸胃炎等），是中心第一批要補的別名；(5) 推送端點、閘道端點與後台頁本輪以規格描述，由另一位同事同時實作，合併後以程式為準。

## 第四十一輪：「covid」「做愛」答不出來，以及智慧問答從此有查詢紀錄

Yulun 實測回報三件事（2026-10-11）：問「covid」答「找不到足夠的官方依據」，但「covid-19」「新冠」可以；問「做愛」查無，但「性行為」可以；還有，問題到底有沒有 log，想知道哪些常被問的問題答不出來。前兩件是同一類病——**民眾怎麼說與官方怎麼寫之間少一座橋**——第三件是找出下一批橋的方法。兩組人平行做，合併後評估集 290 題全過、個資掃描通過。工程契約在 ARCHITECTURE §46、決策 [docs/architecture-decisions.md](docs/architecture-decisions.md) §31。

### 同義詞：優先改資料，引擎只加一條通則（[docs/ask-search-llm.md](docs/ask-search-llm.md) §12、同仁手冊 §41）

- **covid 為什麼查無**：英文名稱是「整字」比對（否則 flu 會命中 influenza），而主檔裡新冠的別名只有 COVID-19、新冠、新冠肺炎，單打 covid 沒有任何名稱對得上，也沒有中文 bigram 可比，相關度閘門就判查無。補別名 COVID、Covid、新冠病毒；「武漢肺炎」維持舊名（問了會提示正名）。
- **做愛為什麼查無**：全站內容一律寫「性行為」，詞彙主檔沒有這個詞，口語展不開。新增詞條「性行為」（別名做愛、性交、上床、嘿咻、房事、親密行為、性接觸；`refs` 留空，讓檢索自己找愛滋、A 肝、M痘、PrEP 與性傳染病專區）。順手補了「交叉免疫」當**詞界**：登革熱教材的「短暫性交叉免疫力」含「性交」兩字，沒有這筆，專業模式問「性交」會答出登革熱——與第三十一輪「急性病毒性A型肝炎」遮住「性病」是同一個機制。
- **引擎通則**：形如「字母-數字」的拉丁名稱（COVID-19）自動也接受字母詞幹（COVID），但有歧義檢查：詞幹已是別的疾病、詞彙、疫苗或國家名，或兩個對象推出同一個詞幹，一律不加，寧可查無也不答錯。H5N1、EV71 這類不套用。現有資料只有 COVID-19 符合，而資料已補 COVID，所以這條規則今天不改變任何答案，是給下一個新病毒株用的保險。
- **為什麼改資料不改程式**：詞彙主檔同事看得到、審得到，一處改同時餵給同義詞展開、答案索引術語、舊名提醒、七語譯名；程式例外只有工程師知道，而且答案引擎的 JS 已用到 240 KB 預算的 238.7 KB，每條特例都吃預算。評估集 r12 新增 BD009–BD016。
- **已知限制**：不在詞典裡的詞系統仍看不見（台語、注音文、錯字、新流行語）；「covid疫苗」中英緊貼時仍認不出疾病（靠 bigram 仍答得出）。所以需要下一段。

### 查詢紀錄：每題送一筆去識別的紀錄，彙整成「常問卻答不出來」報表（[docs/ask-log.md](docs/ask-log.md)、同仁手冊 §42）

- **以前完全沒有紀錄**：引擎整個在瀏覽器裡跑，網站沒有伺服器。現在答案畫完後，前端送一筆只含固定欄位的事件：**已遮蔽個資的問句**（引擎本來就先遮，收件端再遮一次）、語言、版本、結果（答出／相關度低／查無／依據不足／拒答／暫停）、意圖、疾病、前 3 個引用內容 ID、頁面路徑（不含 `?q=`）、時間只到分鐘。**不送** IP、cookie、使用者代號、Referer、User-Agent；瀏覽器開「不要追蹤」或 GPC 就不送。
- **用 fetch keepalive 而不是 sendBeacon**：sendBeacon 關不掉 Referer 與 cookie，收件端若與網站同網域，Referer 會把含原始問句的完整網址送進存取紀錄。fetch 可以 `no-referrer`＋`credentials: 'omit'`，keepalive 一樣送得到。
- **端點是設定不是程式**：`ASK_LOG_MODE`（mock／post／off）與 `ASK_LOG_ENDPOINT`，比照第三十輪的表單端點；post 端點自動進 CSP `connect-src`，設定矛盾建置時報錯。`mock` 只在 `npm run dev` 的本機伺服器才送（伺服器設一個標記 cookie，純靜態主機沒有它就不送），**GitHub Pages 上的原型站不會送出任何紀錄**。模擬收件端寫 `.local/ask-log/YYYY-MM-DD.ndjson`（git 忽略），90 天自動刪除。
- **報表與 k-匿名**：`npm run ask-log:report` 把問句正規化（全半形、大小寫、空白、結尾標點）後彙整，只有被問過 ≥3 次（或 3 個不同日子）的問句才列出文字，低於門檻只計數；對查無的問句自動比對主檔名稱與別名給「疑似同義詞候選」（covid → COVID-19）。後台新頁 `/admin/ask-log/` 看同一份報表，每列一鍵帶入詞彙主檔的新增表單。先不用 LLM；離線 LLM 建議候選、仍由人審核的掛點已在文件寫明。
- **不得進 Git**：原始紀錄與報表都只在 `.local/` 或機關內部儲存；`npm run pii` 範圍不變。給資訊室的確認清單（收件端位置、關掉該路徑存取紀錄、保存期限是否合規、隱私權政策頁加一段）在 docs/ask-log.md §8。

### 教訓

- **「答不出來」多半是詞典缺橋，不是引擎算錯**；而缺哪些橋只有民眾知道。沒有紀錄的問答系統只能靠同事碰巧發現，這輪之後是用數據找。
- **紀錄民眾的輸入要先設計「不記什麼」**：遮兩次、不收 IP、時間到分鐘、k-匿名門檻、原型站根本不送，然後才談記什麼。
- 平行開發的合併衝突一如第四十輪只在檔尾（`.prettierignore`、同仁手冊），兩邊都保留即可；合併後再跑一次完整評估與測試。

## 第四十輪：grokbot 第二批 15 個 issues（#70–#84）——外語誤答、時程地圖措辭、搜尋漏收、答案頁效能、CI 權限隔離

### 智慧問答（#70、#75、#77、#78、#84）

- **印尼文問句只要有「dan」（和）就被當成提示注入拒答（#70，P1）**：注入規則寫 `\bDAN\b` 又不分大小寫，印尼文最常見的連接詞剛好撞上，首頁「給外籍勞工」卡片的預設問題 100% 失敗，拒答訊息還是英文。改成只認大寫 DAN 且要有越獄語境（act as、mode、模式）；新增七語各 20 句以上的一般問句回歸測試（含 dan、ang/at、越南文虛詞），任何一句觸發注入就失敗；拒答與查無文案補齊 id／th／tl（機器初稿，標 `machine-draft` 待多語審核）。**教訓：單字規則要用所有語言的正常句子反向測過，靠補例外清單擋不完。**
- **首頁與各語言頁的預設問句（chips、卡片）從來不在評估集裡（#70、#75）**：民眾第一次按的問題反而沒測。現在 35 句（七語 × 4 chips＋移工卡）都是評估題，題目帶 `preset` 欄位指向介面字串，介面字串改了、評估集沒跟著改，測試就失敗。
- **外語誤答比答不出來更傷（#75）**：同語言語料少時，「有英文片段就用」常常答偏（問「哪裡打流感疫苗」答疫情狀態；移工健檢答「They should check.」）。三個修正：(1) 外語問句先對應到主題錨點（移工、健保、接種紀錄、來臺）再檢索，中文片段更切題就用中文並標「顯示原文」，中文也沒有就老實查無；(2) 最低資訊量門檻（英文 4 詞、中文 6 字、泰文 10 字且要有實詞），脫離上下文沒意義的短句不抽；(3)「在哪裡」問句把接種地點句與「查接種點」行動排第一。
- **服務型問題答非所問（#78）**：「怎麼查小孩的接種紀錄」回整張時程表，站上其實有「接種紀錄與證明補發」服務頁。加「怎麼查／怎麼申請／哪裡」服務意圖，而且**意圖對了還要檢查對象對不對**（服務標題或關鍵詞要與問句重疊，否則單位名裡的「健康」會把結核病補助塞給移工健檢）。影片逐字稿「旁白：」前綴去掉並降權；澄清稿裡引述的謠言原文留在索引（問謠言時才找得到）但標 `noCite`，不能當答案句——**引述不等於主張**。
- **沒產生答案就不要宣稱「AI 整理」（#84）**：查無與拒答卡片以前仍掛 AI 標章與「模型：抽取式整理」，揭露反而不實。改成中性的「未產生答案」說明，稽核編號保留以便事後追查拒答是否合理。
- **新手爸媽常問但站上沒有的內容（#77）**：補接種、未滿 6 個月嬰兒與流感疫苗、懷孕／哺乳接種、嬰兒 RSV，寫成 4 則 FAQ。開發環境連不到官網，只寫無爭議原則，具體數字列成 `pendingItems`，全部 `verification: pending` 交預防醫學辦公室核對；另用一份「肯定式危險說法」清單同時檢查內文與答案句。「漏打怎麼辦」類問句不再走年齡時程表。注意：CI 用固定日期 `BUILD_TODAY=2026-10-01`，這 4 則 FAQ 的發布日是 10-11，在 CI 的評估裡會列為略過，本機與測試（今天日期）有檢查；沒有把發布日往前改，因為那等於偽造。

### 多語頁面（#72、#73、#74、#76）

- **印尼文頁直接顯示 `term.influenza`（#72，P1）**：詞彙主檔的印尼文欄位叫 `id_`（`id` 是識別碼），模板用 `g[lang]` 讀到的就是 ID。改成唯一的 `glossaryTerm()`：該語言 → 英文 → 中文，永不回傳鍵值；**建置時掃 dist 的可見文字**，出現 `term.*` 就失敗（第一次掃就抓到 11 頁，含開發者頁的範例程式，所以 `code`／`pre` 排除）。**教訓：檢查要掃輸出，不掃模板**——漏字是「資料缺譯文」加「模板沒處理退回」組合出來的，看模板找不到。
- **外語頁夾雜中文（#73）**：疫情數字改成「數字＋單位欄位」由 i18n 樣板組字（"29 cases (21 imported)"），判讀依據有譯文才用、沒有就用通用句；清單標題退回中文時統一加 `lang="zh-TW"`、`hreflang` 與「僅有中文」小標（一個 helper，不再每個模板各寫一次）；原型預覽列翻譯。新增建置檢查：非中文頁 CJK 比例超過 15% 列出最差 10 頁（`I18N_CJK_CHECK=warn`，預設不擋）。英文首頁中文比例 2.77% → 0.22%，印尼文首頁 7.72% → 0.24%；仍超標的 65 頁是內容本身沒譯文（網站地圖、申請服務總覽），補翻譯才會降，降下來之前不建議改成 error。
- **切語言後內容消失（#74）**：語言選單標出這頁沒有的語言，點了落在該語首頁時顯示「此頁尚無 X 文版本，可改看英文版」並連回（提示在建置時產生、前端只驗證 `from` 是站內路徑）；en／vi／id 疫苗頁連出官網多語時程表 PDF（標未驗證）；登革熱、腸病毒、結核病、流感四個疾病頁補 id／vi／th／tl 機器翻譯初稿，`status: machine`，**審核前不上線、不進答案索引**，評估題用 `requires: i18n:disease.dengue:id` 綁審核狀態，審核後自動變必考題。
- **來臺旅客與外籍人士沒有入口（#76）**：新增「Visiting or moving to Taiwan」專區（英文為來源語言，中／越／印機翻初稿，`verification: pending` 交檢疫組），外語首頁旅遊卡拆成「出國」與「來臺」。用 `topic` 不用 `page` 型別，因為 `page` 不進答案索引。

### 疫苗時程地圖（#71，P1）

- 3 個月大的寶寶，五合一、B 肝第 1 劑被標成「已超過建議年齡上限」，家長會以為來不及打。根因是主檔只有 `ageMaxMonths`（建議區間上限），畫面只能把「過了建議時間」說成「超過上限」。**「建議時間已過」和「不能再打」是兩個醫療事實，要用兩個欄位存**：超過建議區間 → 「應已完成（若尚未接種請洽醫師安排補接種）」；只有主檔明確填了 `hardLimitMonths` 才會出現「已超過可接種年齡上限」，而且 schema 用 `dependentRequired` 規定有上限就必須有來源與核對旗標，沒出處的醫療限制根本上不了線。目前只有輪狀病毒填 8 個月（未驗證，待承辦人依仿單確認）。
- 結果區改依「公費常規 → 符合條件公費 → 自費（選擇性）」分組；「現在可打」只有自費時加一句提示。新增「已接種劑次」勾選，存在網址 hash（可分享、重新整理不掉、共用電腦不留痕）。補接種與間隔規則**沒有自己編**：只交「各項預防接種間隔時間一覽表」主檔的欄位草案，等承辦人提供資料。

### 全文搜尋與答案頁效能（#79、#80）

- **「兒童健康手冊」搜不到（#79）**：不是斷詞問題。Pagefind 建索引時整段丟掉 `<label>`、`<form>`、`<nav>` 等元素，申請頁「應備文件」勾選清單用 `<label>` 包文字，整份清單都沒進索引，「病歷摘要」「停留天數」也一樣。修法是在餵給 Pagefind 的索引副本裡把 `<form>` 外的 `<label>` 改成 `<span>`，使用者看到的 HTML 不動（`<label>` 是正確的無障礙寫法）。建置後新增**召回自我檢查**：抽 80 頁、160 個 4–8 字中文片段直接查剛建好的索引，低於 98% 建置失敗（整站抽樣 2,012 段：99.8% → 100%）。查無時多一層「逐步去掉前後字」退路並提示改搜了什麼。附帶發現 `pagefind.close()` 不會等檔案寫完，平行測試曾抓到被截斷的 wasm，現在等輸出穩定才關。
- **答案頁手機 Lighthouse 61 分、TBT 2.4 秒（#80）**：直覺是 JSON 太大，CPU profile 卻顯示回答一題 1.1 秒裡約 1.0 秒是**正規式編譯**：1,260 個名稱逐一執行 RegExp，V8 第一次執行才編譯。改成每個名稱先算一段一定會出現的字面子字串預篩，問句裡沒有就不建 RegExp（有測試證明判定與原本完全相同）：Node 上 `answer()` 1,142 → 107 ms。再加索引依語言分片、引擎與索引改成聚焦輸入框才載入、次要 JSON 閒時預取。4 倍 CPU 降速手機實測 `/ask/?q=登革熱`：TBT 4,602 → 約 650 ms，答案出現 5.3 → 1.5 秒，無 q 的初始畫面 121.6 → 86.7 KB 且 0 個 JSON。CI 新增答案頁資料傳輸量門檻（gzip 後估算，445 KB），JS 預算改看「提問後合計」，延後載入不能變成繞過預算的漏洞。**教訓：先量再改，而且要量到能拆開看**；Web Worker 先不做，做法寫在 docs/ask-search-llm.md §11。

### CI 與工程（#81、#82、#83）

## 第三十八輪：同一個修正為什麼在 GitHub Actions 出現好幾次；合併後少一次重複部署

## 第二十三輪：資安優先——原型不給索引、安全標頭基準、快車道看「誰」送、BYOK 收斂、Actions 固定版本

## 治理自動化清單

以下全部由建置時的治理引擎（`scripts/lib/governance.mjs`）自動完成，不需要人記得去做：

- 下次審閱日計算；逾期 → 頁首黃色警示、退出 AI 白名單、開待辦
- 文件新版發布 → 舊版自動標失效（紅色警示、`noindex`、退出索引、301 對照）
- 依據的正本被修訂 → 衍生新聞稿與 Q&A 自動加註、退出白名單、給 owner 7 日待辦
- 反向稽核：宣告過的失效說法（如 MMR「1981 年」）掃全站命中即開待辦
- 譯文 `sourceHash` 對不上 → 標示「中文已更新，譯文待複核」；一級內容未審核不渲染該語言頁
- 資料集更新逾期與授權不合規 → 待辦
- 公告過了截止日 → 自動標「已截止」並退出首頁，不需人工
- 影片製作日早於依據正本現行版生效日 → 自動標過時、退出白名單、開待辦；逐字稿不足 50 字 → 待辦
- 外部連結每日檢查，失效 → 待辦；檢驗送驗時限與主檔通報時限不一致 → 待辦
- 舊站移轉清單中狀態為「待確認」（`pending`）的項目 → 自動開 `migration-pending` 待辦給權責單位；新頁的「舊網址對應」揭露在 `showLegacyUntil` 過後自動隱藏，不需人工；舊網址轉址對照（301）與伺服器格式每次建置自動重算
- 招募階段（即將開放、報名中、已截止、審查與甄試中、結果公布）與採購階段（招標中、已截止、已開標、已決標）由日期與結果推導，截止自動退場、結果滿 90 天自動進歷史、備取有效期過後自動不顯示；結果逾期、備取將到期、外部報名網址失效、決標逾期 → 待辦
- 甄選結果個資遮罩：`nameMasked` 未遮罩、報名編號像身分證字號、正取數超過名額 → 建置失敗；AI 白名單排除名單，答案引擎不唸錄取者
- 採購公告開標後 30 日仍無決標資訊 → 待辦；本站只做入口與狀態，正式公告以政府電子採購網為準
- 檔案資產宣告與建置檢查（規則 22）：宣告的檔案不存在、`sha256`／`bytes` 不符、超過大小、格式或檔名不合法、SVG 含腳本、內文引用了未宣告的 `/files/` → 建置失敗；`content/assets/{id}/` 有檔卻未宣告 → 孤兒檔警告與 `asset-orphan` 待辦
- 圖片 alt 與授權是建置閘門（規則 23）：圖片缺 alt 或 license → 建置失敗；非本署素材缺來源 → `image-license-missing` 待辦
- PDF 沒有文字層又沒附可及性替代版（規則 24）→ 待辦 `attachment-no-accessible-version`
- 發布車道（規則 25）：內容依型別由系統判定車道（快車道、一般車道、緊急發布），CI 檢查全過才可能合併；快車道與緊急發布自動合併、一般車道需 1 位核准；一個 PR 含多種內容取最嚴格；`urgent` 用在不允許的型別 → schema 驗證失敗
- 排程發布（規則 26）：`publishAt` 未到點 → 不渲染、不進索引／sitemap／API／RSS／`llms.txt`，狀態「排程中」；到點後下一次建置（每 2 小時）自動上線
- 上線後複核（規則 26）：快車道與緊急發布的內容上線後，自動開 `post-publish-review` 待辦給公關室，期限上線後 24 小時，逾期升為高優先；PR 逾 SLA 由 CI 加 `sla:breach` 標籤並留言
- 舊站匯出轉換草稿（規則 27）：信心 < 0.6 → 建議人工檢視；草稿一律 `status: review`、不直接進 `content/`；`--apply-migration` 不動 `verified`
- AI 暫停開關 → 全站橫幅，答案頁退回傳統列表
- KPI 與季度 AI 透明報告每次建置重算
- 評估集閘門：版本題只要錯一題，建置失敗
- 旅遊疫情等級表把官方「歷次警示事件」當事件日誌處理：每國每病最新一則、解除即不列；同一疾病同一等級涵蓋 ≥ 50% 國家自動歸為「全球背景提醒」不逐國列；近 30 天新增／調升／調降／解除自動統計；live 分布病態時自動退回人工校對快照並記錄原因

## 資料來源與示意聲明

- **官方來源資料**：旅遊疫情、國家等級與事件流、CKAN 資料目錄由 `scripts/fetch-data.mjs` 抓取到 `data/snapshots/`，每檔記錄來源與時間；CI 排程每日抓取後把快照 commit 回 `main`，所以 repo 內的快照就是當日官方資料（`meta.mode: 'live'`）；抓不到時沿用既有快照並在 `meta.lastLiveAttempt` 記錄原因。
- **示意資料**：疫情態勢的狀態與數字（頁面標「示意」）、致醫界通函卡片、專區的「○○醫院」登入畫面、白名單核准日期、評估集題目與通過率。**不可當作真實疫情或機關決議引用。**
- **內容文字**：範例中的疾病、疫苗與 MMR 建議內容依公開資訊撰寫，用於示範版本鏈與連動；正式上線前須由權責單位逐字審閱。
- 本原型不放真人姓名與個資，承辦人以職稱表示。
- 本專案為概念驗證，與衛生福利部疾病管制署的現行官方網站無隸屬關係，內容不代表官方立場。
